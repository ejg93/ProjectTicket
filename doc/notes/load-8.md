# 부하 8차 — `for share` 몫 가르기와 회차 취소 겹침(I13-10)

`load-7` 의 이긴 선점 p95 227ms(`D13` ≤ 105 밖)를 기계 몫과 `for share` 몫으로 가른다. 같은 할당에서 「오픈 순간」(`load/open-rush.js`)을 세 판 돌렸다 — `for share` 전 이미지 · 지금 이미지 · 지금 이미지 + 판 중 회차 취소.

## 읽은 것

**느린 것은 기계 몫이다.** 행의 산식대로 ② ÷ `load-4` 86ms = 4.0, ② 가 105ms 밖이다. `for share` 몫 ③ ÷ ② = 0.52 로 1.2 아래다 — `for share` 를 뺀 이미지가 오히려 느렸다.
이긴 선점 p95 는 같은 할당·같은 모양에서 180~346ms 로 판마다 크게 흔들린다(이긴 표본 2,000). 서버 쪽 p95 는 39~45ms 라 차이 대부분이 서버 밖(nginx·Tomcat 대기·k6 와 나눈 CPU)이다.

**Hikari 대기는 폴링 몫이다.** 요청의 97% 가 대기열 폴링 GET 이고 `for share` 전 이미지에서도 정점이 139~174 였다. 선점 서버 쪽 평균은 ③ 이 더 짧다.

**회차 취소 겹침에서 풀이 마르지도, 교착도 없었다.** 취소는 200 · 예매 1,000 취소 · 밖에서 0.98초. 5xx 0, 교착·`lock timeout` 0, 초과 판매 0. 취소 앞뒤로 선점 서버 쪽 평균이 17.7ms 로 늘었다(진 선점 409 평균 163ms).

**취소 뒤 폴링 1,573,890 번이 410 이었다** — `open-rush.js` 가 404 만 끝으로 보고 410 `queue-closed` 에는 계속 폴링했다. 회차 화면(`queue-status.tsx`)은 410 에서 멈춘다. ④ 의 Hikari 정점(483~667초)과 요청 수 두 배는 이 스크립트 몫이다. 410 폴링 하나의 서버 평균은 118ms 였다 — 닫힌 회차도 폴링마다 회차 행을 읽는다(`QueueService.requireOpen`).
