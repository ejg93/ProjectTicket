## 읽은 것

**`seats_won` 2,000 은 좌석 수의 두 배인데 초과 판매가 아니다.** 아무도 결제하지 않아서 선점이 5분(ADR 0003) 뒤 만료되고, 스윕이 풀어 준 좌석을 줄 뒤쪽이 다시 잡았다.
DB 로 확인했다 — 좌석 1,000 이 전부 기록 정확히 2건, 둘째 선점의 생성 시각이 첫째 `held_until` 보다 1.9~107초 뒤(1,000쌍 중 앞선 것 0), 한 좌석에 동시에 살아 있는 예매 0.
판이 12분이고 선점이 2초~446초 사이에 섰으니 한 좌석이 두 번 돈 것이다. 행의 닫힘 「`seats_won == SEATS`」는 판 길이가 선점 수명보다 짧다는 전제였다 — **판정을 DB 불변식(좌석마다 동시에 살아 있는 예매 ≤ 1)으로 바꿨다**(정한 것, 계획 밖).

등식 비율 p95 1.12 와 폴링 p95 104ms 는 「35c-재」(1.08 · 121ms)와 같은 자리다 — 입장 뒤 선점을 붙여도 줄이 안 느려졌다.
이긴 선점 p95 86ms 는 nginx·폴링과 CPU 를 나눈 값이다. 서버 쪽 평균은 4~6ms 라 차의 대부분은 문 앞에서 기다린 시간이다(추정 — 구간별 분포를 안 쟀다). `V24` 트리거의 몫은 같은 모양의 V23 판이 없어서 못 가른다.

**구간별 p95 는 못 냈다.** k6 요약은 판 전체 하나고, 앱의 `seat_hold_latency` 는 히스토그램 버킷 없이 sum·count·max 만 낸다 — 그래서 구간 칸은 서버 쪽 평균이다.
입장은 446초에 끝났고 그 뒤로는 선점이 0 이라 「꼬리」 구간은 비었다.
