# ADR 0004 — 설계 점검: 핵심 흐름과 스케일아웃을 잇는 결정

2026-09-14. 청크 9 까지 닫은 뒤 설계 전체를 다시 봤다. 사용자 결정 넷과 그 근거, 그리고 점검이 낸 청크 재편이다.

## 왜 점검했나

분할표는 코드 순서가 촘촘한데 **청크 13 이후를 지탱할 설계 결정이 문서에 없었다.** 선점→결제→확정 흐름과
인스턴스 3대(33)를 잇는 답이 없으면 13·16·33 이 각자 임시 판단으로 간다. 진단 열하나 가운데 큰 것:

| # | 진단 | 어디가 비었나 |
|---|---|---|
| 1 | 세션이 JVM 안에 있다 | `HttpSessionSecurityContextRepository` + 인메모리 `SessionRegistryImpl`. 인스턴스 3대에서 로그인이 안 넘어가고 정지·탈퇴가 다른 대의 세션을 못 끊는다. PLAN 33 은 스케줄러만 봤다 |
| 2 | 예매 상태기계가 없다 | 좌석 상태 셋뿐이다. 스윕(14)과 결제 승인(16)이 같은 행을 두고 다투는 자리에 답이 없다 |
| 3 | 동시성 규약(D4)이 13 뒤에 있다 | 다중 행 잠금 순서·교착·부분 성공·이중 참조·합계 불변식이 13 이 정해야 하는데 P5 는 17 뒤였다 |
| 4 | 예매 생성에 멱등키가 없다 | 재시도가 같은 사람을 두 번 선점시킨다. 16 이 결제에만 걸었다 |
| 5 | 대기열 관문이 무엇을 막는지 없다 | 관문 범위·토큰 묶음·정원 반납·정원 등식이 미정 |
| 6 | 좌석 조회가 규모를 못 버틴다 | 2천 석 × 초당 5천 폴링을 DB 직결로 받는다 |
| 7 | 동시성 테스트가 지금 바탕으로 못 돈다 | `PostgresTestBase` 가 `@Transactional` 이라 스레드 100 개가 각자 트랜잭션을 못 연다 |
| 8 | 회차의 끝이 없다 | 판매 마감·자동 종료·회차 취소가 없다 |
| 9 | 탈퇴·파기·관리자가 없다 | "파기 배치가 한다"는 문장만 있고 그 청크가 없다 |
| 10 | 운영 설정이 비었다 | graceful shutdown, readiness/liveness, 아웃박스 릴레이의 다중 인스턴스 경합 |
| 11 | 시간 규약(P7)이 환불(17) 뒤에 있다 | 구간 경계가 D7 의 시험대인데 순서가 거꾸로다 |

## 결정

| 항목 | 값 | 버린 것과 이유 | 쓰는 청크 |
|---|---|---|---|
| 세션 저장소 | **Spring Session Redis.** `SessionRegistry` 도 Redis 구현 | JWT — 즉시 취소가 안 돼 정지·탈퇴가 만료까지 기다리거나 블랙리스트(결국 Redis)가 필요하고, 쿠키·CSRF·로그아웃을 다시 짠다. nginx sticky — 인스턴스가 죽거나 롤링 배포로 바뀌면 로그아웃되고, 문제를 푼 게 아니라 숨긴 것이다 | 20a, 33, 38 |
| 결제 중 상태 | **`paying` 상태 + 자체 타임아웃(3분).** 스윕은 `held` 만 건드린다 | 결제 시작 때 선점 연장 — 상태가 하나 적지만 「결제 중인가」를 묻는 자리가 없고 결제 화면에서 멈춘 사람이 좌석을 더 오래 쥔다 | 12a, 14, 16 |
| 대기열 관문 범위 | **좌석 선점만.** 결제·취소·조회는 자유 | 예매 흐름 전부 — TTL 이 결제 중에 죽으면 결제를 못 끝내고, TTL 을 늘리면 정원 회전이 느려진다 | 12c, 23 |
| 회차의 끝 | **`sales_close_at` 컬럼(기본 공연 시작 1시간 전) + 자동 종료 스케줄러.** 닫을 때 `held` 는 만료 처리. **회차 취소**(기획사 사정, 전액 환불·알림 일괄)도 청크로 둔다 | 회차 취소 없이 — 아웃박스의 가장 좋은 시험대가 빠진다 | 16a, 17a |

## 결과 — 분할표 재편

**설계 청크 다섯을 코드보다 앞에 세웠다**(`12a`~`12e`). 셋은 이 ADR 과 같은 세션에서 썼다.

| 새 청크 | 무엇 | 자리 |
|---|---|---|
| `12a` | `D3` 예매 상태기계 | 13 앞 |
| `12b` | `D4` 동시성 규약(조건부 UPDATE 근거·잠금 순서·멱등키·불변식) | 13 앞 |
| `12c` | `D12` 대기열 설계 | 21 앞. 13 이 관문 자리를 비워 두려면 지금 |
| `12d` | `D20` 좌석 읽기 모델 + ADR 0005 | 10 앞 |
| `12f` | 동시성 테스트 바탕(롤백 없음) | 13 앞 |
| `16a` | 판매 마감·자동 종료 | 14 뒤 |
| `17a` | 회차 취소 | 17·25 뒤 |
| `20a` | 세션 저장소 Redis | **21 앞**(사용자 선택 — 테스트 Redis 를 이 청크가 들인다), 33 앞. `5a`·`5b` 가 20a 만 기다리면 되게 |
| `5a`·`5b` | 탈퇴·파기 / 관리자 정지 | 20a 뒤 |
| `35a` | 운영 설정(graceful·readiness·가상 스레드) | 30 뒤, 36 앞 |

**고친 행**: 13(멱등키·`paying` 대비·회차 `open` 검사·선행 12a·12b·12f), 16(`paying`), 33(선행 20a), 25(`skip locked`), 28(파티션 키), 17(선행에 P7).

**ADR 번호**: 청크 19 는 0006, 28 은 0007, 34 는 0008 로. 0005 는 좌석 읽기 모델이다.

## 이 문서를 고칠 때

여기 결정은 **12a~12d 문서가 근거로 인용한다.** 값을 바꾸면 그 문서들과 ADR 0003 을 같이 본다.
