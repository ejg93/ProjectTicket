# ADR 0005 — 좌석 읽기 모델: Redis 버전 + 델타 폴링

2026-09-14. 설계 점검(ADR 0004)이 낸 결정이다. 계약과 절차는 `seat-read-model.md`(`D20`).

## 맥락

좌석도가 2초마다 2천 석의 상태를 묻는다(ADR 0003 폴링). 동시 1만 명이면 초당 5천 요청이고, 그것을 `performance_seat` 에 직결하면
DB 가 좌석을 **정하는** 일보다 **보여주는** 일에 먼저 죽는다. 읽기를 쓰기에서 떼어야 한다.

## 저울질한 것

| 안 | 어떻게 | 왜 버렸나 |
|---|---|---|
| DB 직결 + HTTP 캐시 헤더 | 응답에 `max(updated_at)` 로 ETag | ETag 를 만들려면 2천 행을 읽어야 한다. 304 를 주려고 200 만큼 읽는다 |
| `performance.seat_version` 컬럼 | 좌석이 바뀔 때 회차 행을 +1 | 선점마다 회차 행 하나를 갱신한다 — **뜨거운 행**이다. 오픈 초에 초당 수십 트랜잭션이 같은 행의 잠금을 기다린다 |
| SSE 푸시 | 바뀔 때 서버가 민다 | 연결이 인스턴스에 묶인다. 33 에서 Redis Pub/Sub 이 따라온다(ADR 0003) |
| **Redis 버전 + 스냅샷 + 델타** | 커밋 뒤 `INCR`, 버전 키로 스냅샷 캐시, STREAM 으로 변경 로그 | **골랐다** |

## 결정

- 버전은 Redis `INCR`. 쓰기 트랜잭션의 **커밋 뒤**에 올린다. DB 에는 버전이 없다
- 스냅샷은 버전을 키에 넣은 Redis 문자열, TTL 10초. 만드는 것은 버전이 바뀐 뒤 첫 요청뿐
- 변경 로그는 STREAM, 길이 1만. `since` 가 밖이면 410 이고 클라이언트가 전체를 다시 받는다
- 응답은 `ETag` = 버전, `If-None-Match` 로 304
- 좌석 상태는 한 글자(`A`·`H`·`R`), 키는 짧게 — 대역폭이 곧 비용이다

## 결과

- **DB 는 좌석을 정하는 일만 한다.** 보여주는 일은 Redis 가 받고, Redis 가 죽어도 DB 에서 만들 수 있다 — 느려질 뿐 틀리지 않는다
- 청크 10 이 이 계약을 스냅샷 테스트로 굳히고, 41·43 이 그것을 읽는다
- 커밋 뒤 갱신(`afterCommit`)이 `D4` 「트랜잭션 경계」에 규칙으로 들어갔다
- 31 이 잴 것: 304 비율, 스냅샷 생성 횟수/초, 델타 응답 크기 분포
