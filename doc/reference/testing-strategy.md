# 테스트 전략

무엇을 어느 층에서 검증하고, 컨테이너를 어떻게 쓰고, 경쟁을 어떻게 재나.

**바깥 표준을 옮겨 적은 것이 아니라 이 저장소에 이미 있는 테스트에서 뽑은 관례다.** 예시가 전부 실물이다.

## 층

| 층 | 무엇을 검증 | 의존 | 바탕 | 있나 |
|---|---|---|---|---|
| 구조 | 계층·의존·애너테이션 위치 | 클래스 파일 | `ArchitectureTest` | 있다 |
| 단위 | 순수 계산(수수료 구간, 순번→예상 대기) | 없음 | 없음 | 17·21 부터 |
| 통합 | SQL, 제약·트리거, 스프링 배선, 응답 모양 | 컨테이너 DB | `PostgresTestBase` — 롤백 | 있다 |
| **동시성** | **같은 좌석을 둘이 못 잡는다** | 컨테이너 DB, 커밋 | `ConcurrencyTestBase` — **롤백 없음**(12f) | 12f 부터 |
| HTTP | 쿠키 왕복, 필터 순서, 실제 상태 코드 | 컨테이너 DB + 서블릿 | `HttpTestBase`(RANDOM_PORT) | 필요해질 때 |
| 화면 | 오류 `type` 에 따른 분기, 상태에 따른 표시 | jsdom | Vitest + Testing Library | 39 부터 |
| E2E | 프록시·세션 쿠키·CSRF 가 실제로 오가나 | 브라우저 + 서버 둘 | Playwright | 42 부터 |

**MockMvc 로 충분한 자리와 아닌 자리를 가른다.** MockMvc 는 보안 필터 체인을 다 지나므로 401·403·CSRF·관문(23)까지 잰다.
못 재는 것은 **서블릿 컨테이너가 하는 일** — 쿠키의 `Secure`·`SameSite` 실제 동작, 프록시 헤더, 오류 페이지 디스패치다. 그때만 HTTP 층을 연다.

## 레인 셋

| 레인 | 명령 | 무엇 | 태그 |
|---|---|---|---|
| 빠른 | `gradlew test` | 컨테이너 없이 초 단위로 답한다 | 태그 없음 |
| 느린 | `gradlew integrationTest` | 컨테이너를 띄운다. `build` 가 같이 돈다 | `db` |
| **측정** | `gradlew measure` | 수치를 남기는 것 — 1000 스레드 선점(19), 락 비교, 가상 스레드 전후(35a). **`build` 밖이다** | `measure` |

**태그는 바탕이 붙인다.** `PostgresTestBase`·`ConcurrencyTestBase` 를 상속하면 `db` 가 따라오고, 상속하지 않고 DB 를 쓰면 빠른 레인에서 곧바로 빨개진다.
빠뜨릴 자리가 없는 것이 이 방식의 값이다.

**측정 레인이 `build` 밖인 이유**: 결과가 초록·빨강이 아니라 **숫자**다. 숫자는 `doc/notes/` 에 적고 ADR 이 읽는다.
CI 러너에서 재면 값이 흔들려서 뜻이 없다 — 손으로 돌리고 기계 사양을 같이 적는다.

## 컨테이너

`PostgresTestBase.Containers` 가 `postgres:17-alpine` 을 띄운다 — `docker-compose.yml` 과 같은 이미지다. 갈리면 테스트가 통과해도 운영에서 깨진다.

| 규칙 | 왜 |
|---|---|
| 재사용을 켠다(`~/.testcontainers.properties`) | 기동이 JVM 당 한 번에서 기계당 한 번으로 준다. 안 켜도 테스트는 통과하고 느릴 뿐이다 |
| `@ServiceConnection` | 연결 정보를 손으로 안 옮긴다. fork 별 DB 를 가르는 날(아래)에는 못 쓴다 |
| Redis 컨테이너는 21 이 같은 `Containers` 에 더한다 | 바탕이 둘이면 새 테스트가 어느 쪽을 상속할지 매번 판단한다 |
| **마이그레이션을 고쳤으면 재사용 컨테이너를 지운다** | Flyway 체크섬이 안 맞아 전부 빨개진다. 아직 안 풀린 가지에서만 고친다(`D14`) |

### fork 는 하나다 — 늘리는 조건

느린 레인은 지금 fork 하나로 돈다. **2분을 넘으면 늘린다.** 늘리는 순간 필요한 것:

- fork 마다 DB 이름을 가른다(`ticket_test_<worker>`) — 롤백 없는 테스트의 정리가 남의 fork 행을 지운다
- `@ServiceConnection` 을 버리고 `JdbcConnectionDetails` 를 직접 만든다
- Redis 는 논리 DB 번호로 가른다

ProjectShop 이 이 길을 갔고 그 코드가 참고다. **지금 안 하는 이유**는 문제가 안 생겼는데 미리 만들면 그 코드가 맞는지 확인할 방법이 없어서다.

## 격리

**통합 층은 트랜잭션째 되돌린다**(`@Transactional`). 테스트가 넣은 것이 다음 테스트에 안 남는다.

**되돌아가는 것은 데이터뿐이다.** 스레드·컨텍스트에 남는 것은 바탕이 따로 비운다 — 테스트마다 붙이면 빠뜨리고,
빠뜨렸을 때 깨지는 것이 **남의 클래스**라 원인을 찾을 실마리가 없다.

| 남는 것 | 어디서 비우나 | 왜 남나 |
|---|---|---|
| `SecurityContextHolder` 의 인증 | `PostgresTestBase.clearSecurityContext` | MockMvc 가 스레드를 나눠 쓴다 |
| 감사 `ATTEMPT` 행 | `PostgresTestBase.purgeCommittedAuditLogs` | `REQUIRES_NEW` 라 롤백에 안 쓸린다. 정리도 별도 트랜잭션이고, 보존 가드를 그 트랜잭션에서만 끈다 |
| `CsrfFilter` 의 저장소 | `CsrfCookieTest.restoreOurCsrfRepository` | `csrf()` 후처리기가 공유 필터의 저장소를 바꿔 끼우고 컨텍스트에 남긴다(`stack.md`) |

**시드는 그대로 쓴다.** 마이그레이션이 넣은 동의 항목·(12 뒤로) 공연장을 테스트가 다시 만들지 않는다 — 실제 초기 데이터 위에서 도는지가 검증 대상이다.

### 제약 위반은 테스트 하나에 하나

위반이 나면 Postgres 가 그 트랜잭션을 어보트시킨다. 같은 테스트의 다음 문장은 `25P02` 로 죽고, **둘째 단언이 재려던 제약이 아니라 어보트를 잰다.**
`SeatUniquenessTest` 가 그렇게 깨졌고 위반 하나당 테스트 하나로 갈랐다.

### 강제 지점을 재는 테스트는 그 지점을 친다

트리거·check 를 재려면 서비스가 아니라 **SQL 을 직접 던진다.** 서비스를 거치면 앱 검증이 먼저 막아서 제약이 도는지를 못 본다.
`AuditImmutabilityTest`·`SeatUniquenessTest`·`PerformanceStateTest` 가 그 모양이다.

**무엇을 치고 무엇을 안 치나** — 한 행 안에서 끝나는 `check`(값 목록·길이·형식)는 안 잰다(`D14` 「불변식」 — 제약은 언제나 막는다). 유일 제약은 그것이 **도메인 불변식**이면(복제 두 번·결제당 환불 하나·좌석 기록 한 줄) 직접 친다 — 점검 1차(`I1`)가 그 기준으로 셋을 더했다. 트리거는 전부 친다.

**트리거끼리의 순서를 안다.** `before update` 트리거가 check 보다 먼저 걸린다 — 값 목록(check)을 재려다 전이 트리거 문구를 받는다. 재려는 것을 먼저 만나는 문장을 고른다.

### 테스트가 강제 지점을 우회하면 적는다

정리가 트리거를 끄는 자리(감사 보존 가드)가 그 예다. **우회를 숨기지 않고 주석에 밝히고, 가드 자체를 따로 재는 테스트가 있어야** 검증이 비지 않는다.

## 경쟁을 보려면 롤백을 끈다 — `ConcurrencyTestBase`

동시성 테스트는 통합 층에 있으면서 **트랜잭션만 없다.** 테스트가 트랜잭션을 열고 있으면 다른 스레드가 그 안의 변경을 못 보고 잠금도 안 걸려서 **경쟁 자체가 안 일어난다.**
HTTP 층으로 올리는 것과 다르다 — 서블릿이 필요한 게 아니라 **커밋**이 필요한 것이다.

```
@SpringBootTest        (@Transactional 없음)
@AutoConfigureMockMvc  (안 쓰지만 컨텍스트 캐시 키를 PostgresTestBase 와 맞춘다)
@Tag("db")
@Import(PostgresTestBase.Containers::class)
abstract class ConcurrencyTestBase
```

| 규칙 | 왜 |
|---|---|
| 각 스레드가 **서비스를 직접** 부른다. 서비스의 `@Transactional` 이 스레드마다 자기 트랜잭션을 연다 | MockMvc 는 스레드 안전이 보장되지 않고 필요하지도 않다 — 재는 것은 SQL 의 경합이다 |
| **출발선을 맞춘다** — `CountDownLatch` 로 다 모아 두고 한 번에 놓는다 | 스레드를 만드는 시간이 선점 하나보다 길어서, 그냥 띄우면 먼저 만들어진 스레드가 혼자 끝낸다 |
| `runConcurrently(n)` 이 그 일을 하고 스레드별 `Result` 를 돌려준다. 커넥션 풀은 기본 10 이라 DB 에는 열이 10 씩 들어간다 | 재는 것은 스레드 수가 아니라 같은 행을 두 트랜잭션이 동시에 건드릴 때 DB 가 어떻게 하나다. 풀을 키우면 속성 때문에 컨텍스트가 갈린다 |
| **만든 것을 직접 지운다.** 계정 이메일·기획사 코드·공연장 이름에 접두사(`concurrency-`)를 붙이고 그것만 지운다. `ConcurrencyTestBaseTest` 가 바탕 자체를 잰다 | 남의 층이 만든 것을 지우면 그쪽이 조용히 깨진다 |
| 정리를 **한 트랜잭션**으로, **시작할 때도 한 번** | 합계 등식이 지연 트리거라 자식만 지운 채 커밋되면 터진다. 앞선 실행이 죽으면 재사용 컨테이너에 데이터가 남는다 |
| 회차·좌석은 테스트가 만든다. 시드를 안 쓴다 | 시드 좌석을 잡으면 정리가 시드를 지운다 |

### 「승자 하나」를 무엇으로 재나

```
스레드 N (100) 이 같은 좌석 하나를 동시에 선점한다
  성공(201)          = 정확히 1
  실패(409 seat-taken) = N - 1
  DB: performance_seat 그 행의 status = 'held', reservation_id 가 성공한 예매
  DB: 그 좌석을 가리키는 reservation_seat 행 = 1
```

**넷 다 본다.** 응답만 보면 「둘 다 201 인데 DB 는 하나」를 놓치고, DB 만 보면 「둘 다 409 인데 좌석은 잡혔다」를 놓친다.

### 막았다는 것만 보지 말고 안 막으면 무엇이 나는지도 본다

교착 회피는 id 오름차순 `for update` 하나가 장치다(`D4`). **그 정렬을 지워도 테스트가 통과할 수 있다** — 플래너가 두 요청에 같은 순서를 돌려주면 순환이 안 생긴다.
그래서 **잠그는 순서를 손으로 엇갈리게 만든 대조 테스트**를 같이 둔다: 스레드 A 는 `[7, 8]`, B 는 `[8, 7]` 순서로 잠그게 해서 교착이 실재함을 못박고,
그 위에서 정렬을 켜면 사라지는 것을 본다.

## 오늘 날짜에 기대지 않는다

**테스트가 달력을 타면 특정 날에만 깨진다.** 그런 실패는 늦게 드러난다.

| 무엇 | 어떻게 |
|---|---|
| 수수료 구간(17)·예상 대기(21) 같은 **계산** | 날짜·시각을 인자로 받는 순수 함수로 내리고, 단위 테스트가 고정값을 넣는다 |
| 만료·타임아웃(14·16) | **DB 시각이 시계다**(`D7`). 앱 시계를 고정해도 SQL 의 `now()` 는 안 움직이므로, 만료를 재는 테스트는 `held_until = now() - interval '1 second'` 로 **이미 지난 행을 직접 넣는다** |
| 값이 채워졌나만 본다 | `isNotNull()` 은 달력을 안 탄다 |
| 관통 흐름 | 날짜를 안 넣는다. 이어지는지가 목적이다 |

`Thread.sleep` 으로 시간을 흘리지 않는다 — 5분을 기다릴 수 없고 5초로 줄이면 운영과 다른 값을 잰다.

## 스냅샷 테스트 — 응답 계약

좌석 현황(`D20`)처럼 **화면이 그대로 읽는 응답**은 형식을 파일로 굳힌다. 필드 하나가 빠지면 화면이 조용히 깨지는데 타입 검사가 못 잡는 자리다.

| 항목 | 값 |
|---|---|
| 형식 | JSON. 값이 흔들리는 필드(`version`·시각·id)는 자리표시로 바꾼 뒤 비교한다 |
| 위치 | `src/test/resources/snapshots/<테스트>.<이름>.json` |
| 갱신 | 시스템 속성 `-Psnapshot.update=true` 로 다시 쓴다. **갱신은 계약 변경이라 이력에 적는다** |

## 두 층에 흩어진 문자열의 대조

화면이 `error.type` 으로 분기하고 백엔드가 그 슬러그를 바꾸면 **그 가지는 죽고 사용자는 영영 기본 문구만 본다.** 빌드도 타입 검사도 통과한다.
그래서 이 대조는 화면이 아니라 **백엔드 테스트**로 둔다 — 실물 목록(`ErrorCode`)이 거기 있어서다. 39 가 세운다.

| 테스트 | 무엇을 대조하나 |
|---|---|
| `ErrorTypeScreenTest` | 화면이 분기하는 슬러그 ⊆ `ErrorCode` 의 슬러그 |
| `ScreenLengthTest` | 화면 입력칸의 `maxLength` = 요청 `data class` 의 `@Size(max)` |
| `StateMachineDocTest`(13) | 코드의 전이표 = `state-machines.md` 의 전이표 |

**대개 한쪽만 본다.** 화면이 쓰는 것이 서버에 있어야 하고 그 반대는 아니다.

## 테스트 이름

`snake_case` 로 **문장**을 적는다 — `hundred_threads_one_winner`, `refused_optional_item_leaves_a_false_row`. 실패 목록이 그대로 읽히는 것이 목적이다.
클래스는 `*Test`. `@DisplayName` 을 안 쓴다 — 이름이 두 벌이면 한쪽이 낡는다.

## 알려진 구멍은 테스트로 고정한다

지금 못 막는 것을 알면 **그 구멍이 열려 있음을 재는 테스트**를 둔다. 누가 고치면 그 테스트가 빨개져서 「고쳤다」가 기록된다.
감사 트리거가 테이블 주인에게 무력한 것(`4a`)이 첫 후보다.

## 커버리지

JaCoCo 가 붙어 있고 **문턱은 없다.** 문턱을 정하는 것은 `D18` 이고, 지금 박으면 그 값이 근거 없이 관례가 된다.
보는 것은 **강제 지점을 재는 테스트가 있나**지 줄 수가 아니다.

## 이 문서를 고칠 때

**레인·태그·바탕 이름은 `build.gradle.kts` 와 같아야 한다.** `P4` 가 그 대조 테스트를 세운다. 바탕을 더하면 「층」 표에 행을 더한다.
