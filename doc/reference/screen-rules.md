# 화면·문구 규약

화면이 **권한·오류·빈 상태를 어떻게 그리나**. 서버가 무엇을 내려주는지는 `api-guidelines.md`(D5)가 정했고, 여기서는 그것을 받은 화면이 무엇을 하는지를 정한다.
어느 층에서 그리나는 `frontend-rules.md`(D16)다.

## 기준

| 대상 | 기준 자료 |
|---|---|
| 접근성 | **KWCAG 2.2**(국가표준 KS X OT0003, WCAG 2.1 기반) |
| 약관 표시 | 약관규제법 제3조제1항 |

**접근성은 범위 밖으로 둘 수 있는 것이 아니다.** 장애인차별금지법 제20조·제21조가 민간 사업자에게도 걸린다(단계적 적용이 2015년에 끝났다) — 법 요건이라 출처 순위 1위다(`D14` 「축 1」).
되돌리는 비용도 다르다. 나중에 붙이면 **고치는 것이 아니라 다시 짜는 것**이 된다. `41` 이 그 순위로 결정했다 — 분할표의 「SVG 좌석도」를 버리고 체크박스로 갔다.

**문구 문체가 `CLAUDE.md` 와 갈린다.** 그쪽은 개발자가 읽는 글이라 평서형이고, 화면은 사용자가 읽는 것이라 존댓말이다. 아래 「문구」 절을 본다.

### 시각 디자인은 아직 안 정한다

**색·간격은 `globals.css` 의 토큰이고 그것이 전부다**(사용자 결정, `P9`). Tailwind 도 디자인 스킬도 지금은 안 들인다.

이유는 순서다 — 화면 다섯 중 셋(`43`·`44`·`45`)이 아직 없고, 스타일은 다 생긴 뒤 청크 하나로 한 번에 입힌다.
색·간격은 **토큰이라 나중에 바꿔도 마크업이 안 바뀐다.** 접근성과 반대다 — 그쪽은 마크업이라 먼저 건다.
그때까지 지키는 것은 둘뿐이다: 색을 컴포넌트에 박지 않고 토큰으로 쓴다, 순수 `#000000`·`#ffffff` 를 안 쓴다.

**다크모드는 그 청크가 정한다.** 지금 토글도 `prefers-color-scheme` 도 없다.

## 화면 지도

**어떤 화면이 있고 어디서 어디로 가나.** 화면을 만들기 전에 여기 먼저 적는다 — 지도가 없으면 링크를 걸 대상이 있는지 없는지를 그때그때 판단하게 된다.

| 경로 | 무엇을 | 누가 보나 | 어느 청크 |
|---|---|---|---|
| `/` | 홈. 지도만 준다 — 목록을 여기서 또 읽지 않는다 | 누구나 | `39` **완료** |
| `/events` | 공연 목록. 판매 중인 회차가 있는 공연만(`40a`) | 누구나 | `40b` **완료** |
| `/events/[eventId]` | 공연 상세 — 등급·회차. 회차를 고르면 좌석으로 | 누구나 | `40b` **완료** |
| `/performances/[performanceId]` | 좌석 선택·선점. 보는 것은 누구나, **누르면 로그인** | 누구나 | `41`·`42` **완료** |
| `/reservations/[reservationId]` | 예매 하나의 지금 — 결제·카운트다운·티켓. 상태가 화면을 고른다 | 로그인(본인) | `42` **완료** |
| `/queue/[performanceId]` | 대기열 — 순번·예상 대기·자동 입장. 입장 토큰은 이 탭의 `sessionStorage` 에 회차별로 둔다 | 로그인 | `43` **완료** |
| `/me` | 내 계정 | 로그인 | `39` **완료** |
| `/me/reservations` | 내 예매 목록·취소. 취소는 두 단계 — 미리보기 액수를 보인 뒤 「이 금액으로 취소」 | 로그인 | `44b` **완료** |
| `/me/withdraw` | 탈퇴. 비밀번호를 다시 받는다 — 틀려도 로그인 화면으로 안 튕긴다(`api()` 가 `login-failed` 401 을 던진다) | 로그인 | `44c` **완료** |
| `/login`·`/signup` | 로그인·가입(약관 동의가 같이 있다) | 비로그인 | `39` **완료** |
| `/terms`·`/privacy` | 이용약관(`consent_item.body`)·개인정보 수집·이용 안내(정형 넷, 개인정보 보호법 제15조). `GET /api/consent-items/{code}` 를 그린다. 처리방침(제30조)은 아직 없다 — `39-3` | 누구나 | `39-1` **완료** |
| `/organizer` | 내 공연 목록 · 「공연 등록」. 링크는 `/me` 에서만 — 머리글은 세션을 안 읽는다 | 기획사 | `45b` **완료** |
| `/organizer/events/new` | 공연·등급 등록(구역은 홀 목록에서 고른다) | 기획사 | `45b` **완료** |
| `/organizer/events/[eventId]` | 공연 하나 — 회차 등록·오픈·취소, 회차마다 팔린 수. 매출은 `45c` | 기획사 | `45b` **완료** |
| (지도에 없는 주소) | `not-found.tsx` — 공연 목록으로 가는 길을 준다 | 누구나 | `40b` **완료** |

**기획사 경로를 접두어로 가른다.** 서버의 `/api/organizer/**` 와 같은 모양이라 권한 판정 자리가 한 군데다(아래 「권한 없는 것은 숨긴다」).

### 아직 없는 화면은 자리표시로 둔다

지도에 있는데 아직 안 만든 화면은 **「준비 중」 페이지를 놓고 링크는 건다.** 링크를 안 걸면 화면이 생길 때마다 넣었다 뺐다 하고, 걸고 404 면 사용자가 고장으로 본다.
자리표시는 **그 화면을 만드는 청크가 지운다.** 남아 있으면 그 청크가 안 끝난 것이다.
지도의 경로마다 `app/<경로>/page.tsx` 가 있는지는 `frontend/src/test/screen-map.test.ts` 가 잰다(`39-1`) — 지도에 먼저 서고 파일이 따라온다.

### 화면마다 다시 정하지 않는 것

| 것 | 정한 것 | 왜 |
|---|---|---|
| 목록 넘김 | **번호 페이징**(`/events?page=`) | 서버가 `page`·`size` 로 내려준다(`D5`). 주소가 곧 상태라 뒤로 가기·새로고침·링크가 저절로 된다(`D16`). 「더 보기」는 상세에 들어갔다 돌아오면 첫 쪽으로 떨어진다 |
| 시각 | **KST 로 그린다**(`format.ts`) | 관람일이 KST 달력일이라(`D7`) 브라우저 시간대를 쓰면 다른 나라에서 화면의 날짜와 환불 계산의 날짜가 갈린다 |
| 금액 | 정수 원, `154,000원` | `D5` 「값의 형식」 |
| 없는 값 | **`null` 이면 그 줄을 안 그린다**, 0 으로 안 바꾼다 | `min_price` 가 `null` 인 공연을 0원으로 그리면 공짜 공연과 안 갈린다(`40b`) |
| 공연 사진 | **없다** | 스키마에 이미지가 없다. 자리표시 사진도 안 넣는다 — 진짜처럼 보이는 가짜가 포트폴리오에서 제일 먼저 들킨다 |
| 토스트 | **안 만든다** | 우리 오류는 전부 폼 제출의 결과거나 페이지 전체다(아래 「오류」). 사라지는 알림은 낭독기가 놓친다 |

## 셸

모든 화면이 같은 머리를 쓴다. `<main>` 은 `app/layout.tsx` 가 한 번만 그리고 화면은 그 안을 채운다 — 표지(landmark)가 하나여야 건너뛰기 링크가 가리킬 대상이 하나다.

머리는 **로그인 여부를 안 본다.** 거기서 세션을 읽으면 모든 화면이 매 요청 백엔드를 한 번 더 두드리고 그 판정이 화면의 판정과 두 벌이 된다.

**셸이 드는 셋**(`39-1`): 맨 앞 「본문으로 건너뛰기」(`#main` — 초점이 오면 보인다), 발의 약관·처리방침(전자상거래법의 고지라 모든 화면에서 닿아야 한다), 첫 진입의 뼈대(`app/loading.tsx`).

## 접근성

**마크업을 쓰는 모든 청크가 지킨다.** KWCAG 2.2 전부를 여기 옮기지 않는다 — 우리 화면에서 실제로 걸리는 것만 적는다.

| 항목 | 규칙 | 우리 화면의 어디 |
|---|---|---|
| 키보드 | 마우스로 되는 것은 키보드로도 된다. 초점이 보인다 | 좌석도가 체크박스인 이유(`41`). `.seat:has(input:focus-visible)` 이 초점을 그린다 |
| 레이블 | 모든 입력에 `label`. `placeholder` 로 대신하지 않는다 | `Field` 가 라벨을 든다. 좌석은 `aria-label` 에 **구역·열·번호·상태·가격**을 다 넣는다 — 숫자만 읽어 주면 문맥을 기억해야 한다 |
| 색만으로 알리지 않는다 | 색은 같은 사실을 한 번 더 말하는 자리다 | 좌석 상태가 이름에 글자로 든다(`선택 가능`·`선점됨`·`판매됨`). 필수 동의는 「(필수)」라고 쓴다 |
| 오류 안내 | 어느 입력이 왜 틀렸는지를 글로 알린다 | 아래 「오류」 |
| 동적으로 바뀌는 것 | `role="alert"`·`role="status"`·`role="timer"` | 폼 오류·고른 좌석 수·카운트다운. 안 붙이면 낭독기 사용자에게는 아무 일도 안 일어난다 |
| 제목 구조 | `h1`~`h6` 을 건너뛰지 않는다 | 전부 |
| 언어 | `<html lang="ko">` | `layout.tsx` |
| 대체 텍스트 | 뜻이 있는 이미지에 `alt` | 아직 이미지가 없다 |
| 대비비 | 본문 4.5:1, 큰 글자 3:1 | 토큰이 이것을 통과해야 한다. **axe 가 못 본다**(jsdom 에 CSS 가 없다) — 사람이 본다 |
| 반복 영역 건너뛰기 | 머리를 지나 본문으로 가는 링크를 맨 앞에 | `39-1` |

**기계가 보는 것 둘**(`D18`): eslint 의 `jsx-a11y` 전체 규칙(정적 — JSX 에 적힌 것)과 `src/test/axe.ts`(그려진 DOM — 조건부 마크업과 이어진 이름).
둘 다 **빠뜨린 것만 잡는다** — `alt="이미지"` 처럼 성의 없이 채운 것과 대비비·탭 순서는 못 본다. 그쪽은 이 표가 사람이 볼 규칙이다.

**비활성 대신 숨긴다는 규칙(아래)이 접근성과 어긋나지 않는 이유**: 비활성으로 두면 낭독기가 「읽을 수 있고 만질 수 없다」고 말한다. 안 그리면 없는 것이다.
**좌석은 예외다** — 선점·판매된 좌석은 `disabled` 로 둔다. 없는 것이 아니라 **남이 잡은 것**이고, 그 사실이 자리를 고르는 정보다.

### 약관의 중요한 내용은 강조한다

**약관규제법 제3조제1항이 요구한다** — 약관은 한글로 쓰고 중요한 내용을 부호·색채·굵고 큰 문자 등으로 명확하게 표시한다.
`consent_item.body` 가 마크다운인 이유가 이것이다(`V3`). 강조를 원문에 넣어 두면 화면이 살려서 그린다 — 통짜 텍스트로 뿌리면 이 의무를 못 지킨다. 굵게와 색을 같이 쓴다(색만으로 알리지 않는다).

## 권한 없는 것은 숨긴다

**할 수 없는 조작은 화면에 안 그린다.** 비활성화해서 보여주지 않는다. 기능의 존재 자체가 안 새게 하려는 것이다 — 관리자 기능이 비활성 상태로 보이면 그 시스템에 무엇이 있는지가 드러난다.

**판정은 서버가 한다.** 화면은 `role` 을 읽지 않는다(`D16`). 기획사 화면은 서버 컴포넌트가 `/api/organizer/…` 를 부르고 **403 이면 페이지 전체로 「권한이 없다」를 그린다**. `notFound()` 로 안 바꾼다 — `D5` 가 「역할이 없는 경로 접두는 403, 존재를 숨길 자원이 없다(경로 자체가 공개다)」로 정했고, 숨기는 것은 **남의 자원**(404)뿐이다.
머리의 링크도 역할로 안 가른다. 권한 없는 사람에게 기획사 링크가 보이는 대가보다 판정이 두 벌 되는 대가가 크다 — 링크 자체는 `45` 가 그 화면을 세우며 정한다.

## 오류는 자리를 가려서 보여준다

**사용자가 고칠 수 있는 것과 아닌 것을 가른다.** 전부 인라인이면 붙일 자리가 없는 오류를 못 그리고, 전부 페이지 전체면 어느 칸이 틀렸는지를 사용자가 찾아야 한다.

| 오류 | 어디에 | 예 |
|---|---|---|
| 그 입력칸의 값이 규칙에 안 맞음 — 화면이 안다 | **그 칸 아래 인라인**, `aria-invalid` | 비밀번호 15자 미만 |
| **어느 칸인지 서버가 안 알려줌** | **폼 전체.** 칸을 지목하지 않는다 | 로그인 실패 |
| 요청은 옳은데 지금 상태가 안 맞음 | **폼 전체.** 제출의 결과라 그 자리다 | 이미 가입된 이메일, 남이 먼저 잡은 좌석, 카드 거절 |
| 권한이 없음 (403) | **페이지 전체.** 「권한이 없다」를 그린다 — 404 로 안 바꾼다(`D5`) | 기획사 화면에 직접 주소로 들어옴 |
| 자원이 없음 (404) | **페이지 전체**(`not-found.tsx`) | 없는 공연·회차·예매 |
| 인증이 끊김·없음 (401) | **로그인 화면으로 보낸다** | 다른 기기에서 탈퇴됨, 로그인 없이 선점 |
| 서버 오류 (5xx) | **페이지 전체**(`error.tsx`) | |

**폼 전체 오류는 제출 버튼 위, 입력칸 아래에 두고 `role="alert"` 를 붙인다.** 위에 두면 스크롤한 화면에서 안 보이고, 아래에 두면 방금 누른 자리 바로 옆이다 — `39` 가 위에 뒀다가 `40b` 가 고쳤다.

### 모르는 칸을 지목하지 않는다

**서버가 어느 칸이 틀렸는지 일부러 안 알려주는 오류가 있다.** 로그인 실패가 그렇다 — 없는 계정인지 틀린 비밀번호인지 가르면 **가입 여부를 물어보는 도구**가 된다(`D9`).
그럴 때 **입력칸에 `aria-invalid` 를 걸지 않는다.** 두 칸에 다 걸면 맞은 이메일까지 「잘못된 입력」이라고 낭독된다 — 사실이 아닌 것을 말하는 것이라 색만으로 알리는 것보다 나쁘다.

**어느 칸인지는 `type` 으로 안다.** 상태 코드로는 못 가른다 — `422` 하나에 여러 뜻이 뭉쳐 있다. **`detail` 문자열로 분기하지 않는다.** 문구를 다듬는 순간 화면이 깨진다.

### 결과는 오류가 아니다

결제 거절·무응답은 서버가 201 에 `status` 로 주는 **결과**다(`D5`). 오류로 그리면 「서버가 고장났다」로 읽힌다 — 결과로 그리되 자리는 폼 전체 오류와 같다(`42`).

### 401 은 조용히 보내지 않는다

로그인 화면으로 갈 때 **왜 나갔는지를 알린다.** 아무 설명 없이 로그인 화면이 나오면 사용자는 자기가 뭘 잘못 눌렀다고 생각한다.
표시는 `?reason=` 이고 로그인 화면의 `REASON_TEXT` 가 문구를 든다 — **모르는 값은 아무것도 안 그린다.** 주소는 사람이 고칠 수 있어서 여기 없는 값이 올 수 있다.
「만료됐다」는 **만료였음을 아는 입구만** 말한다(`D16` 「401 은 입구가 잡는다」).

## 빈 상태

**아무것도 없는 것과 조건에 맞는 게 없는 것을 가른다.** 아무것도 안 그리면 고장과 구분이 안 되고 사용자는 새로고침을 누른다.

| 상황 | 무엇을 쓰나 | 우리 예 |
|---|---|---|
| 데이터가 아직 없다 | 무엇을 하면 생기는지, 또는 언제 다시 오면 되는지 | 「판매 중인 공연이 없습니다. 예매가 열리면 여기에 표시됩니다.」 — 파는 것은 기획사지 사용자가 아니라 「무엇을 하면」이 없다 |
| 필터·검색 결과가 0건 | 조건을 바꾸라고 알린다. **조건을 지우는 길을 같이 준다** | 아직 필터가 없다 |
| 있는데 지금 살 것이 없다 | 「없는 것」과 가른다 | 열린 회차가 없는 공연은 404 가 아니라 빈 회차 목록이다(`40a`) |

권한이 없어서 0건인 경우는 **여기 안 온다** — 그 화면에 애초에 못 들어온다.

## 기다리는 동안

| 상황 | 어떻게 |
|---|---|
| 첫 진입 | 뼈대(`app/loading.tsx`, `39-1`). 이 파일이 없으면 브라우저가 이전 화면에 머물러 누른 것이 안 먹은 것으로 보인다 |
| 이미 있는 화면을 갱신 | **기존 내용을 두고** 흐리게 한다. 목록이 통째로 사라졌다 나타나면 보던 자리를 잃는다 |
| 사용자가 누른 버튼 | 그 버튼만 잠그고 문구를 바꾼다(`SubmitButton`). 화면 전체를 막지 않는다 |
| 시간이 정해진 기다림 | **서버가 준 마감 시각**을 센다(`Countdown`). 남은 초를 받아 세면 시계가 느린 브라우저에서 끝난 선점이 살아 있는 것처럼 보인다. 0 이 되어도 화면이 상태를 안 바꾼다 — 바꾸는 것은 서버다 |

## 되돌릴 수 없는 조작

| 무엇 | 무엇을 요구하나 |
|---|---|
| 탈퇴 | **비밀번호 재확인**. 확인 대화상자만으로는 부족하다 — 세션을 훔친 사람이 탈퇴까지 하면 주인이 계정을 영영 잃는다 |
| 예매 취소 | 확인 대화상자에 **환불 금액**을 적는다(`44`, `D6`). 「취소하시겠습니까?」만으로는 무엇을 잃는지 모른다 |
| 좌석 선택 해제·동의 철회 | 없음 — 다시 할 수 있다 |

되돌릴 수 있는 것에 확인을 붙이지 않는다. 확인이 흔해지면 사용자가 읽지 않고 누른다.

## 문구

### 화면 문구는 존댓말이다

**`CLAUDE.md` 의 「글 작성 규칙」은 여기 안 걸린다.** 그쪽은 개발자가 읽는 글(문서·주석·커밋)의 규칙이라 평서형을 쓴다. 화면은 사용자가 읽는 것이라 존댓말을 쓴다.

```
문서·주석·커밋   철회는 기존 행을 고치지 않고 한 줄을 더한다
화면            수신 동의를 해제하시겠습니까?
```

**`screen-text.test.ts` 가 막는다**(`39`, `D18`). `.tsx` 의 한글 문자열을 AST 로 걷어 `다` 로 끝나는 것(앞이 `니` 인 존댓말은 빼고)을 찾는다 — 주석이 평서형이라 정규식으로는 못 잰다.
**못 보는 것 셋**: 변수로 조립한 문장 · 서버가 내려준 문구 · `~했음` 같은 다른 반말 어미(0건이라 목록을 안 만들었다 — 하나 나오면 그때).

### 지키는 것

| 규칙 | 나쁨 | 좋음 |
|---|---|---|
| 사용자를 탓하지 않는다 | 이메일을 잘못 입력하셨습니다 | 이메일 형식이 올바르지 않습니다 |
| 다음에 무엇을 할지 적는다 | 오류가 발생했습니다 | 잠시 후 다시 시도해 주세요 |
| 시스템 용어를 안 쓴다 | 422 Unprocessable Content | 한 번에 잡을 수 있는 좌석 수를 넘었습니다 |
| 내부 값을 그대로 안 보인다 | `held` | 결제 대기 |
| 과하게 사과하지 않는다 | 대단히 죄송합니다. 불편을 끼쳐드려… | 잠시 후 다시 시도해 주세요 |

`CLAUDE.md` 의 나머지 규칙(중복 금지, 미사여구 금지, 필요한 만큼만)은 화면에도 그대로 걸린다. 존댓말이라고 길어질 이유가 없다.

### 서버 문구를 그대로 안 쓴다

`D5` 의 `detail` 은 **평서형이고 개발자가 읽는 것에 가깝다.**

```
서버 detail    이미 잡힌 좌석이 있다
화면            방금 다른 분이 먼저 잡은 좌석이 있습니다. 좌석 현황을 새로 고쳐 주세요.
```

화면은 `type` 을 보고 **자기 문구를 고른다.** `detail` 을 그대로 찍으면 문체가 갈리고, 서버 메시지를 다듬는 순간 화면 문구가 같이 바뀐다.

## 이 문서를 고칠 때

화면을 만들다가 여기 없는 상황이 나오면 **그 상황을 여기 먼저 추가한다.** 화면마다 다르게 그리기 시작하면 사용자가 같은 뜻을 매번 새로 배워야 한다.
새 화면은 「화면 지도」에 먼저 선다. 시각 디자인을 정하는 청크가 오면 「기준」의 그 절을 통째로 다시 쓴다.
