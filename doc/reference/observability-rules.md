# 관측 규약

로그에 무엇을 어떻게 남기고, 요청 하나를 어떻게 되찾고, 무엇을 재나.

## 감사 로그와 다르다

| | 관측 로그 (이 문서) | 감사 로그 (`audit_log`, 4) |
|---|---|---|
| 답하는 질문 | 이 요청이 어디서 느려졌나, 왜 실패했나 | 누가 무엇을 했나 |
| 저장 | 파일(`logs/ticket.log`, 7일·200MB) | DB. 3년 |
| 개인정보 | 안 담는다 | 행위 주체의 **id** 를 담는다 |

### 감사 기록은 사건 종류가 전파를 정한다

`AuditLog.Kind` 를 부르는 쪽이 고르고, 그 값이 트랜잭션 전파를 정한다.

| 종류 | 전파 | 언제 |
|---|---|---|
| `ATTEMPT` | `REQUIRES_NEW` | **업무가 안 일어난 것 자체가 사실**인 사건 — 로그인 실패 |
| `OUTCOME` | `REQUIRED` | 업무가 성립해야 사실이 되는 사건 — 가입, 로그인, 회차 오픈, 예매 확정 |

전부 `REQUIRED` 면 실패한 시도가 정의상 한 줄도 안 남는다. 전부 `REQUIRES_NEW` 면 롤백된 일이 「했다」로 남는다.
종류를 인자로 받는 이유는 새 사건을 더할 때 안 고르면 컴파일이 안 되게 하려는 것이다.

**대가**: `REQUIRES_NEW` 는 커넥션을 하나 더 잡고, 테스트 롤백에 안 쓸려 바탕이 따로 지운다(`D8`).

## 추적 ID

요청이 들어올 때 발급하고 그 요청의 **모든 로그 줄**에 찍는다.

| 항목 | 값 |
|---|---|
| 헤더 | `traceparent`(W3C Trace Context). B3 를 안 쓴다 — 관측 도구를 붙이는 30 에서 갈아엎지 않으려고 |
| 발급 | Micrometer Tracing + Brave. 헤더가 오면 이어받고 없으면 만든다. 샘플링 1.0 |
| 로그에 | `traceId` **뒤** 6자리, `spanId` **앞** 4자리 |
| 오류 본문 | `trace_id` 전체. **성공 응답에는 안 넣는다** |

**뒷자리인 이유**: Brave 128비트 ID 의 앞 8자리가 생성 시각이라 같은 초의 요청이 앞에서 전부 같아 보인다. 스팬은 반대로 앞자리 — 루트 스팬 ID 가 추적 ID 의 하위 64비트와 같아서 둘 다 뒷자리면 같은 글자가 두 번 보인다.

**값을 만드는 곳은 하나다.** `ProblemFactory` 도 `Tracer` 에서 가져온다. 헤더를 따로 파싱하면 깨진 헤더에서 둘이 갈리고, 사용자가 불러 준 ID 로 로그를 못 찾는다.
`RequestTraceTest` 가 응답의 ID 와 로그의 ID 가 같은지 잰다.

## 형식 — 사람이 읽는 텍스트

```
10:39:06.601Z INFO  [7a32a0,5c29] c.p.t.o.RequestLogFilter : GET /api/me 401 136ms
```

시각은 UTC 에 `Z`(`D7`). JSON 이 아닌 이유는 수집기가 없어서다 — 30 이 Prometheus 를 붙여도 로그는 텍스트고, 수집기가 붙으면 `logback-spring.xml` 만 바꾼다.
프로필별로 형식을 안 가른다 — 안 돌려본 설정은 쓸 때 깨져 있다.

## 레벨 — `ERROR` 는 사람이 개입할 것에만

| 레벨 | 무엇 | 예 |
|---|---|---|
| `ERROR` | 사람이 고쳐야 하는 것 | 500, 스케줄러 실패, DB·Redis 끊김 |
| `WARN` | 지금은 도는데 이상한 것 | 교착 재시도, 승인이 늦어 좌석을 못 준 것(`payment_late`), Redis 강등 |
| `INFO` | 업무가 지나간 흔적 | 요청 한 줄, 선점·확정·만료, 4xx |
| `DEBUG` | 개발 중에만 | 스윕이 훑은 행 수 0 |

**4xx 는 `ERROR` 가 아니다.** 좌석이 이미 잡힌 것(409)도 서버가 제대로 동작한 결과다. `ERROR` 를 아무 데나 섞으면 아무도 안 본다.

## 개인정보는 안 찍는다

**식별자만.** 이름·이메일·연락처는 로그에 안 넣는다. 내용이 필요하면 id 로 DB 를 본다.

```
찍는다     account_id=7 reservation_id=1042 performance_id=3 status=reserved amount=308000
안 찍는다  email=… name=… card=…
```

| 규칙 | 실물 |
|---|---|
| 객체를 통째로 찍지 않는다 | `SignupRequest`·`LoginRequest` 는 `toString` 을 재정의해 비밀번호를 뺐다. 그래도 `log.info("{}", request)` 를 안 쓴다 |
| 요청 본문을 찍는 필터를 안 만든다 | `RequestLogFilter` 는 메서드·경로·상태·시간뿐. 쿼리 문자열도 뺀다 |
| 예외 메시지에 값을 안 넣는다 | `TicketException` 의 `detail` 은 식별자까지만 — 그대로 응답에 나간다 |
| 감사에도 같다 | 로그인 실패 감사에 이메일이 없다. 파기 예외로 3년 남는 자리다 |

마스킹을 안 쓰는 이유: 금지 목록은 새 필드가 생길 때마다 갱신해야 하고 빠뜨리면 조용히 샌다. 애초에 안 찍으면 뺄 것도 샐 것도 없다.

## 무엇을 찍나

| 자리 | 레벨 | 담는 것 | 있나 |
|---|---|---|---|
| 요청 한 줄 | INFO | 메서드·경로·상태·ms. 예외로 빠져나가면 상태 대신 예외 이름 | 있다 |
| `/actuator/*` | — | **안 찍는다.** 30초마다 두드리는 것이 하루 2,880줄이다 | 있다 |
| 업무 사건 | INFO | 선점·확정·만료·취소·오픈·종료 — 식별자와 결과만 | 13~ |
| 스케줄러 한 회 | INFO | 무엇을 몇 건. 0건이면 DEBUG | 14~ |
| 외부 호출 | INFO | 모의 PG — 대상·ms·결과 | 16 |
| 교착 재시도 | WARN | 몇 번째, 어느 좌석 id | 13 |

**시작·끝 두 줄로 안 쓴다.** 끝 줄에 시간이 있으면 시작 줄이 답하는 것이 「왔다」뿐이고, 로그가 두 배가 된다.

## 지표 — 이름 규약 (30 이 든다)

`<도메인>.<무엇>` 소문자 점 표기. 태그는 값이 유한한 것만 — `performance_id` 를 태그로 두면 회차마다 시계열이 는다.

| 이름 | 종류 | 태그 | 무엇 |
|---|---|---|---|
| `seat.hold.attempts` | 카운터 | `result`(`won`·`taken`·`rejected`) | 선점 시도와 결과 |
| `seat.hold.latency` | 히스토그램 | | 선점 트랜잭션 ms |
| `seat.sweep.expired` | 카운터 | | 스윕이 되돌린 좌석 |
| `reservation.confirmed` · `reservation.cancelled` | 카운터 | `reason` | |
| `queue.length` · `queue.active` | 게이지 | | 회차 합. 회차별은 로그로 |
| `queue.admitted` | 카운터 | | |
| `queue.wait_seconds` | 히스토그램 | | 진입→입장 |
| `queue.gate_rejected` | 카운터 | `reason` | |
| `seat.snapshot.built` | 카운터 | | 읽기 모델이 DB 에서 스냅샷을 만든 횟수(`D20`) |

**`MetricNamesTest`(30)가 이 표와 코드를 대조한다.** 대시보드 패널은 ADR 0003 — 선점 성공률, 대기열 길이, 응답 p95, 오류율.

## 지금 안 하는 것

| 항목 | 왜 |
|---|---|
| 로그 수집기·JSON | 서버 1대. 30 뒤 인스턴스 셋이 되면 다시 본다 |
| OpenTelemetry 내보내기 | 헤더 형식만 맞춰 뒀다 |
| 경보 | `ERROR` 가 사람에게 닿는 경로. 30 의 Grafana 가 첫 자리다 |
| 이상징후 탐지 | 감사 로그가 쌓인 뒤에 |

## 이 문서를 고칠 때

지표를 더하면 표에 먼저 적고 `MetricNamesTest` 가 실물과 대조한다. 로그에 새 필드를 넣고 싶으면 **그 값이 식별자인지**부터 묻는다.
