# 성능 목표 (`D13`)

**무엇을 얼마나 빠르게 해야 하나**를 숫자로 정하고, 그 숫자를 **어떻게 재는지**까지 같이 적는다.
재는 방법이 없는 목표는 목표가 아니라 바람이다.

근거는 31 의 1차 부하(`doc/notes/load-1.md`)다. 32 가 그 숫자를 보고 이 문서를 썼고, **35 가 2차 부하로 대조한다.**

## 먼저 — 이 숫자가 무엇의 숫자인가

1차는 **노트북 한 대**에서 쟀다. k6·nginx·앱 셋·Postgres·Redis 가 같은 CPU 를 나눠 썼다.
그래서 여기 적는 목표는 「이 서비스가 낼 수 있는 최대」가 아니라 **「이 구성에서 이만큼은 나와야 한다」의 바닥**이다.

바닥을 목표로 두는 이유는 하나다 — **깨졌을 때 무엇이 나빠졌는지 알아채려고** 둔다.
최대를 목표로 두면 기계가 바뀔 때마다 목표가 흔들려서 회귀를 못 본다.

## 목표

| 무엇 | 목표 | 1차 실측 | 왜 이 값인가 |
|---|---|---|---|
| 좌석 선점 p95 | **≤ 350ms** (동시 300) | 290ms | 실측에 20% 여유. 이 값이 대기열이 지키는 상한(`D12`)의 실체다 |
| 좌석 선점 p95 | **≤ 100ms** (동시 100) | 47ms | 한가한 시간의 응답. 두 배 여유를 뒀다 — 여기서 늘면 DB 쪽이 변한 것이다 |
| 전체 HTTP p95 | **≤ 900ms** (동시 300) | 743ms | 로그인(bcrypt)이 섞인 값이다. 순수 예매 경로는 위 선점 p95 가 답한다 |
| 처리량 | **≥ 450 req/s** | 565 req/s | 실측의 80%. 인스턴스 셋 + 풀 10 의 바닥이다 |
| 5xx 비율 | **0** | 0 | 경합·정원 초과·줄 서기는 4xx 다. **5xx 는 우리가 못 한 것**이라 하나도 안 받는다 |
| 대기열 입장 대기 p95 | **≤ 2 × (순번 ÷ R)** | 4.0초(300명, R=20/초) | 절대값이 아니라 **등식 대비**로 본다 — 300명이면 이론값이 15초 언저리고 실측은 그보다 빨랐다 |
| 좌석 현황 조회 | **스냅샷 생성 ≤ 판 변경 횟수** | — | 절대 수가 아니라 비율이다. 폴링 수에 비례해 늘면 캐시가 안 먹는 것이다(`D20`) |

**목표를 안 정한 것**: 기동 시간·메모리·DB 커넥션 수. 지금 아픈 자리가 아니고, 아파지면 그때 숫자를 정한다.

## 어떻게 재나

| 무엇 | 어디서 |
|---|---|
| 선점 p95·처리량·5xx | `load/seat-rush.js`(k6). 돌리는 법은 `load/README.md` |
| 대기열 대기 | 같은 스크립트의 `admission_wait_ms` |
| 앱 쪽 같은 시간대 | Grafana 대시보드 `ticket-core`(30) — `seat.hold.latency`·`queue.wait_seconds`·`queue.length` |
| 스냅샷 비율 | `seat.snapshot.built` 와 판 변경 횟수 |

**부하와 대시보드를 같이 본다.** k6 는 「밖에서 본 시간」이고 지표는 「안에서 본 시간」이라,
둘이 갈리면 그 차이가 곧 네트워크·프록시·큐 대기다.

## 목표를 못 맞추면

| 무엇이 넘었나 | 먼저 볼 것 |
|---|---|
| 선점 p95 | 커넥션 풀(10)과 선점 트랜잭션. `pg_stat_statements` 가 기동 인자로 켜져 있다 |
| 전체 HTTP p95 | 로그인 비중. bcrypt 비용 10 이 응답의 얼마인지 갈라 본다 |
| 처리량 | 인스턴스 수와 풀. 33 의 `--scale` 을 올려 선형으로 느는지 본다 |
| 5xx | **즉시 본다.** 목표가 0 이라 하나만 나와도 원인을 찾는다 |
| 대기열 대기 | 입장 속도 R 과 스케줄러가 한 대에서만 도는지(33 의 락) |

## 다시 정하는 조건

1. **k6 를 다른 기계로 뺀 뒤** — 지금 숫자는 부하 생성기와 서버가 CPU 를 나눠 쓴 값이다
2. **커넥션 풀을 올린 뒤** — 풀 10 이 병목이면 다른 숫자가 나온다(가상 스레드 측정도 같은 이유로 결론을 못 냈다)
3. ADR 0003 의 입장 속도 R·정원 C 를 바꾸면 — 대기열 목표는 그 값에서 나온다

**고칠 때는 근거가 된 측정 노트를 같이 적는다**(`load-1`·`load-2`…). 숫자만 바뀌고 근거가 없으면 다음 사람이 되돌릴 수가 없다.
