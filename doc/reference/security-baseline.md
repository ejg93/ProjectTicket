## 인증

### 비밀번호

| 항목 | 값 | 근거 |
|---|---|---|
| 해시 | bcrypt 비용 10. 테스트는 4(`PostgresTestBase`) | `DelegatingPasswordEncoder` 라 `{bcrypt}` 접두가 붙어 알고리즘을 바꿔도 옛 해시가 검증된다 |
| 길이 | 15~64 | NIST SP 800-63B Rev.4 — 단독 인증수단이면 15자 SHALL. MFA 가 없다 |
| 문자 | ASCII 출력 가능 문자만 | bcrypt 의 72바이트 절단을 아예 안 만든다. 한글은 글자당 3바이트다 |
| 조합 강제 | **안 한다** | 같은 문서의 SHALL NOT |
| 블록리스트 | **아직 없다.** 열려 있는 SHALL 위반 | `3b` |

규칙의 출처는 `Password` 애너테이션 하나다. 두 자리에 두면 한쪽만 고치는 날이 온다.

### 로그인이 흘리면 안 되는 것

| 무엇 | 어떻게 막나 |
|---|---|
| 계정 존재 (문구) | 없는 계정·틀린 비밀번호·정지 계정이 **같은 `login-failed`** |
| 계정 존재 (시간) | `TicketUser.isEnabled` 는 항상 true — 정지 판정을 bcrypt **뒤**로 옮겼다. 앞에서 걸면 정지 계정만 수십 ms 빨라 시간 차가 샌다 |
| 무차별 대입 | `3a` — 10분에 5회, 10분 잠금. Redis 가 필요해서 21 뒤 |

### 세션

| 항목 | 지금 | 20a 뒤 |
|---|---|---|
| 저장소 | JVM 메모리 | **Redis**(Spring Session). 인스턴스 셋이 같은 세션을 본다(ADR 0004) |
| 무활동 만료 | 30분 | 같다 |
| 절대 만료 | 12시간. `AbsoluteSessionTimeoutFilter` | 같다 |
| 세션 고정 | 로그인 앞에서 **세션을 버리고 새로 만든다** + `changeSessionId` | 같다 |
| 레지스트리 | `SessionRegistryImpl`(메모리) — 자리만 있다 | Redis 구현. 정지(5b)·탈퇴(5a)가 여기서 세션을 끊는다 |

**절대 만료가 로그인 시점부터 세려면 세션을 새로 만들어야 한다.** `changeSessionId()` 는 ID 만 바꾸고 생성 시각을 안 바꾼다 — 마무리 2차 독립 리뷰가 잡았다.

### 계정이 죽었는데 세션이 살아 있는 구간

로그인할 때만 상태를 보면 **이미 로그인한 다른 기기가 안 막힌다.** 두 겹으로 막는다.

| 겹 | 무엇 | 있나 |
|---|---|---|
| 생존 확인 | `AccountLivenessFilter` 가 요청마다 `deleted_at is null and status = 'active'` 를 본다. 죽었으면 세션을 버리고 401 | 있다 |
| 세션 만료 | 정지·탈퇴가 레지스트리에서 그 계정의 세션을 전부 만료 | 5a·5b(20a 뒤) |

한 겹씩만 두면 실패 방식이 갈린다 — 세션 만료만 두면 계정을 죽이는 경로가 늘 때 등록을 빠뜨리는 순간 조용히 뚫리고, 생존 확인만 두면 요청마다 DB 를 친다.

### 쿠키

| 쿠키 | `HttpOnly` | `SameSite` | `Secure` | 왜 |
|---|---|---|---|---|
| `TICKETSESSION` | 켠다 | `Lax` | `SESSION_COOKIE_SECURE`(기본 꺼짐) | 스크립트가 못 읽는다. 남의 사이트 POST 에 안 붙는다. 로컬이 http 라 기본은 끄고 **https 로 올리면 켜야 한다** |
| `XSRF-TOKEN` | **끈다** | `Lax` | 같다 | JS 가 읽어 헤더에 실어야 한다 |

### CSRF

쿠키(`XSRF-TOKEN`)로 내리고 헤더(`X-XSRF-TOKEN`)로 받는다. 헤더는 평문, 파라미터는 XOR(`SecurityConfig.csrfTokenRequestHandler`).
로그인 뒤 토큰을 회전하고(`CsrfAuthenticationStrategy`), 로그아웃이 쿠키를 지운다(`CsrfLogoutHandler`). 실패는 403 `forbidden` 본문이다.

`SameSite=Lax` 가 겹치지만 대체하지 않는다.

**테스트의 함정**: `SecurityMockMvcRequestPostProcessors.csrf()` 는 공유 필터의 저장소를 바꿔 끼우고 컨텍스트에 남긴다. 진짜 경로를 재는 테스트가 스스로 되돌린다(`stack.md`).

## 대기열 토큰과 멱등키

| 값 | 형식 | 묶음 | 왜 |
|---|---|---|---|
| 활성 토큰(`D12`) | 무작위 32바이트, base64url, Redis 저장 | 계정 + 회차. 관문이 셋을 대조 | 서명 토큰이 아닌 이유는 **반납**이다. 서명은 만료 전에 못 죽인다 |
| 멱등키(`D4`) | 클라이언트 UUIDv4 | 계정별 유일 | 남의 키로 남의 응답을 재생할 수 없다 |

관문은 **선점에만** 걸린다(ADR 0004). Redis 가 죽으면 관문은 **닫힌다**(503) — 열면 대기열이 지키려던 폭발이 DB 로 간다.

## 입력과 출력

**검증은 서버에서 한다.** 프론트 검증은 편의고 방어가 아니다.

| 자리 | 방식 |
|---|---|
| 요청 본문 | Bean Validation. `@RequestBody` 에 `@Valid` 가 없으면 검증이 조용히 안 돈다 — `ArchitectureTest` 규칙으로 내린다(13) |
| 열거값 | enum 으로 받는다. 모르는 값은 400(`D5`) |
| SQL | 이름 바인딩만. 상태 리터럴도 바인딩(`D14`) |
| 정렬 컬럼 | 허용 목록. 바인딩이 안 되는 자리다 |
| 좌석 id | 요청의 회차 것인지 SQL 에서 같이 본다(`D4`) — 다른 회차 좌석을 섞어 보내도 안 잡힌다 |
| HTML | React 기본 이스케이프. `dangerouslySetInnerHTML` 금지(39) |

## 감사

무엇을 남기나는 ADR 0003 — 돈·권한·상태가 바뀌는 것. 실패한 시도는 `ATTEMPT` 로 롤백을 넘어 남는다(`D10`).

**권한이 트리거 앞에 선다**(`4a`, `V20`). 앱은 붙자마자 `ticket_app` 역할을 입고(`connection-init-sql`),
그 역할에는 `audit_log` 의 `update`·`delete`·`truncate` 가 없다 — 문장이 트리거까지 못 간다.
지울 수 있는 역할은 `ticket_purge` 하나고, 파기 배치가 **그 트랜잭션 안에서만** 입는다(`set local role`).

| 층 | 무엇을 막나 | 누가 뚫나 |
|---|---|---|
| 권한(`V20`) | 앱의 모든 `update`·`delete`·`truncate` | 역할을 바꾸는 문장을 남기는 사람 — 흔적이 남는다 |
| 트리거(`V3`) | 권한이 있는 자리의 고침·이른 삭제 | 표 주인(`disable trigger`)·슈퍼유저(`session_replication_role`) |

**아직 남은 것**: 접속 **계정**은 하나다. 계정을 가르면 역할을 바꾸는 문장조차 못 쓰는데, 그것은 배포가 정해진 뒤(36·38)의 일이고
그때 `ticket_app`·`ticket_purge` 에 로그인을 붙이면 된다. 지금은 **한 겹 낮췄지 없앤 것이 아니다.**

| 교착 | 1회 재시도 | `D4` |

## 비밀 관리

`.env` 는 커밋하지 않는다. `.env.example` 에 이름만. DB 비밀번호는 개발용이고 다른 데 안 쓴다. gitleaks 가 CI 에서 커밋 이력을 훑는다.
