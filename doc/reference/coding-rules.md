# 코딩 규약

**코드를 쓰는 모든 청크에 걸린다.** 다만 통짜로 읽지 않는다 — `backend/CLAUDE.md` 의 표가 건드리는 것에서 이 문서의 절로 보낸다.

**바깥 표준을 옮겨 적은 것이 아니라 이 저장소 코드에 이미 성립한 관례를 뽑은 것이다.** 그래서 예시가 전부 실물이고,
어긋난 자리가 생기면 코드를 고치거나 이 문서를 고친다.

## 계층

```
Controller  →  Service  →  JdbcClient
  HTTP 를 안다   도메인을 안다   SQL 만 안다
```

| 규칙 | 왜 |
|---|---|
| 컨트롤러는 서비스만 부른다 | DB 접근이 컨트롤러에 섞이면 같은 조회가 화면마다 복제된다 |
| 서비스가 트랜잭션 경계다 | 컨트롤러에 걸면 요청 하나가 통째로 한 트랜잭션이 되고, 밖에서 부를 때 경계가 사라진다 |
| 상태 코드는 `error` 패키지가 정한다 | 흩어지면 `D5` 의 표와 대조할 대상이 사라진다 |

**이 표는 `ArchitectureTest` 가 지킨다.** 문서(5위)에서 테스트(4위)로 내린 것이다.
규칙이 막는 것은 컨트롤러가 `JdbcClient` 를 직접 드는 것이고, `*Query` 클래스를 부르는 것은 허용이다 — 그쪽은 읽기 쪽 서비스다.

**예외 둘.** `HealthController` 는 `JdbcClient` 를 직접 쓴다 — DB 에 질의가 실제로 나가는지가 그 엔드포인트의 목적이라
서비스를 거치면 검사할 것이 사라진다. `MeController` 도 같다 — 세션이 가리키는 행 하나를 그대로 읽는 것이라 도메인 판단이 없다.

## 예외

**서비스는 무엇이 잘못됐는지만 말하고, 그것이 몇 번인지는 안 정한다.**

```kotlin
// 서비스
throw TicketException(ErrorCode.REQUIRED_CONSENT_MISSING, "필수 동의 항목이다: $code")

// ApiExceptionHandler 가 상태 코드와 본문을 정한다
```

서비스가 `ResponseStatusException` 을 던지면 웹을 알게 된다. 배치나 이벤트 소비자에서 같은 서비스를 재사용할 때 어색해지고,
상태 코드가 코드 전체에 흩어진다.

**예외 클래스를 종류마다 안 만든다.** 오류 목록이 `ErrorCode` 한 화면에 있어야 `D5` 의 표와 눈으로 대조된다.
클래스로 흩으면 「우리가 몇 가지 오류를 내나」에 답하려고 패키지를 뒤져야 한다.

**`type` 슬러그는 계약이다.** 프론트가 상태 코드가 아니라 `type` 으로 분기하므로(`D5`) 바꾸면 화면이 깨진다.
문구(`title`)는 다듬어도 된다.

**보안 필터가 끊는 자리는 예외 처리기가 못 잡는다.** 401 은 `ProblemEntryPoint`, 403 은 `ProblemAccessDeniedHandler` 가
같은 `ProblemFactory` 로 본문을 만든다 — 두 자리가 각자 만들면 같은 오류가 형태만 다르게 두 벌 나간다.

## 트랜잭션

| 규칙 | 왜 |
|---|---|
| 경계는 서비스의 `@Transactional` | 위 「계층」과 같은 이유다 |
| 여러 테이블을 한 뜻으로 바꾸면 한 트랜잭션 | `SignupService` 가 계정과 동의를 같이 커밋한다. 갈리면 동의 없이 개인정보를 든 계정이 생긴다 |
| **자기 호출로는 전파가 안 걸린다** | 같은 클래스 안에서 부르면 프록시를 안 지나 `REQUIRES_NEW` 가 무시된다 |

셋째가 `AuditLog` 와 `AuditLogWriter` 가 나뉜 이유다. 실패한 로그인은 부르는 쪽이 롤백되는데도 남아야 해서
전파를 바꿀 자리가 따로 필요했다.

## 값

**요청·응답·조회 결과는 `data class`.** 상태를 들고 도는 것만 보통 클래스다.

`data class` 는 불변이라 만든 뒤에 안 바뀌고 `equals`·`toString` 이 공짜다.
DB 에서 읽은 행을 `Map<String, Any>` 로 들고 다니지 않는다 — 키 오타가 실행할 때만 드러난다.

**예외가 하나 있다.** `TicketUser` 는 `data class` 가 아니다 — 인증이 끝나면 비밀번호 해시를 지워야 하는데(`D9`)
불변 객체는 그 요청에 응답할 방법이 없다.

**`toString` 이 비밀을 흘리는 자리를 본다.** `data class` 의 기본 `toString` 은 모든 필드를 찍는다.
`SignupRequest`·`LoginRequest` 가 그것을 재정의한 이유가 평문 비밀번호다.

### 빈 값에 뜻을 싣지 않는다

「없다」와 「비어 있다」가 다른 뜻이면 타입으로 가른다. 널 하나에 두 뜻을 담으면 읽는 쪽이 매번 어느 쪽인지 물어야 한다.

DB 도 같다 — `account.deleted_at` 이 수명이고 `status` 가 업무 상태다. 한 컬럼에 섞으면 복구할 때 이전 상태를 잃는다.

### 플랫폼 타입을 그냥 받지 않는다

`JdbcClient.list()` 의 원소는 Java 에서 와서 Kotlin 이 `T?` 로 본다. 행이 널일 수 없는 조회면 `filterNotNull()` 로 걷어내고,
널일 수 있으면 그대로 둔다. **`!!` 로 덮지 않는다** — 덮으면 왜 널이 아닌지가 아무 데도 안 남는다.

`!!` 를 쓸 자리가 정말 있으면 **왜 널이 아닌지를 주석으로 댄다.**

## Kotlin 으로 쓴다

Java 를 옮겨 적지 않는다. ProjectShop 에서 포팅한 코드도 옮기면서 아래대로 고쳤다.

| 쓰는 것 | 안 쓰는 것 |
|---|---|
| `data class` | 손으로 쓴 getter·setter·builder |
| 널 타입(`String?`) | `Optional` |
| `when` | 긴 `if-else` 사슬 |
| `enum.entries.firstOrNull { }` | `values()` 를 도는 스트림 |
| 확장 함수 | 정적 유틸 클래스 |
| 기본 인자 | 오버로드 여럿 |

**`when` 에 `else` 를 안 둔다** — 열거값이 늘면 컴파일러가 빠진 가지를 짚어 준다. `else` 를 두면 새 값이 조용히 기본 가지로 간다.

## SQL

| 규칙 | 왜 |
|---|---|
| 이름 바인딩만 쓴다 | 값을 이어 붙이면 인젝션이다(`D9`) |
| `select *` 를 안 쓴다 | 컬럼이 늘면 응답이 조용히 바뀐다 |
| 상태 리터럴을 SQL 에 안 박는다 | 열거형이 유일한 출처다. `AccountStatus.ACTIVE.code` 를 바인딩한다 |
| **좌석 상태를 바꾸는 것은 조건부 UPDATE** | `D4`. 읽고 판단하고 쓰면 그 사이에 남이 끼어든다 |

마지막 줄이 이 저장소의 핵심 규칙이다. 좌석은 `update … where status = 'AVAILABLE'` 의 **갱신 행 수**로 판정하고,
행 수가 기대와 다르면 롤백한다. `select` 로 먼저 확인하는 코드를 쓰지 않는다.

## 마이그레이션

| 규칙 | 왜 |
|---|---|
| `V` 번호를 건너뛰거나 되쓰지 않는다 | Flyway 가 순서를 어긴 것으로 보고 멈춘다 |
| 적용된 파일을 고치지 않는다 | 체크섬이 안 맞아 기동이 막힌다. 고칠 것이 있으면 새 `V` 를 판다 |
| 새 `V` 를 더하면 `HealthControllerTest` 의 수를 올린다 | 올리는 것을 잊으면 거기서 빨개진다. 그 자리가 「기동 경로를 지났나」를 재는 곳이다 |
| 제약에 이름을 준다 | 이름이 없으면 오류 문구로 어느 규칙이 걸렸는지 못 짚는다 |
| **시드를 마이그레이션에 안 넣는다** — `local` 프로필의 `DemoSeeder` 가 서비스를 불러 만든다 | 운영 스키마와 데모 데이터가 섞이면 지울 것을 못 고른다. 마이그레이션으로 넣으면 그 번호가 적용 이력의 최고가 돼서 **다음 마이그레이션이 막힌다**(12, 사용자 선택) |

## 열거값을 어디에 두나

**코드의 `enum` 과 DB 의 `check` 제약 양쪽에 둔다.** 한쪽만 두면 다른 쪽으로 들어오는 값을 못 막는다.

| 자리 | 무엇을 막나 |
|---|---|
| Kotlin `enum` | 코드가 없는 값을 쓰는 것 |
| DB `check` | 배치·시드·`psql` 로 들어오는 값 |

**둘이 갈리는 것을 테스트가 막아야 한다.** 목록이 두 벌이면 한쪽에만 값을 더하는 날이 오고, 그날 증상은
「그 계정만 이유 없이 막힌다」처럼 원인과 멀다. `AccountRole`·`AccountStatus` 가 지금 이 모양이고,
값이 늘면 `EnumConstraintTest`(`I2-1`)가 열거형과 `check` 를 대조한다.

**모르는 값을 조용히 넘기지 않는다.** `of()` 가 없는 값에 예외를 던지는 이유다 — 기본값으로 떨어뜨리면
새 값이 들어온 계정만 이유 없이 권한을 잃고 오류도 로그도 안 남는다.

## 길이 상한은 앱과 DB 양쪽에 둔다

앱 검증(3위)은 새 입구가 생기면 빠뜨린다. DB 제약(2위)은 어디로 들어오든 막는다.

**두 값이 갈리는 것을 막을 자리가 필요하다.** 지금은 이메일 254 와 이름 50 이 `EmailAddress`·`SignupRequest` 와
`account_email_length_check`·`account_display_name_length_check` 에 두 벌 있다. 갈리기 시작하면 대조 테스트를 세운다.

**단위를 맞춘다.** 표준이 옥텟으로 말하면 DB 도 `octet_length` 로 잰다 — `length` 는 글자 수라 비ASCII 에서 다른 값이 된다.

## 주석

**무엇을 하는지가 아니라 왜 그런지를 적는다.** 코드가 답하는 것을 주석이 다시 말하면 둘이 어긋나는 날이 온다.

적을 값이 있는 것:

- 버린 선택지와 버린 이유
- 플랫폼 사실(「이렇게 안 하면 조용히 안 먹는다」)
- 이 줄이 무엇을 막는가
- 출처가 법·표준이면 조문·절 번호

**주석이 부르는 것이 실물과 맞아야 한다.** 마무리의 대조가 그것을 본다.

## 테스트

**두 레인이다**(`D8`). 컨테이너를 안 타는 것은 `test`, 타는 것은 `integrationTest` 다.

| 무엇 | 어디 |
|---|---|
| 계층·구조 규칙 | `ArchitectureTest`(빠른 레인) |
| 제약·트리거·뷰 | `PostgresTestBase` 를 상속(느린 레인) |
| 관통 흐름 | MockMvc + `PostgresTestBase` |

**`db` 태그를 빠뜨릴 자리가 없다.** 컨테이너가 `PostgresTestBase` 에만 있어서 DB 를 쓰려면 상속해야 하고,
상속하면 태그가 따라온다. 상속하지 않고 DB 를 쓰면 빠른 레인에서 곧바로 빨개진다.

**강제 지점을 재는 테스트는 서비스가 아니라 그 지점을 친다.** `AuditImmutabilityTest` 가 SQL 을 직접 던지는 이유다 —
코드에 `update` 를 안 쓰는 것만으로는 `psql` 로 한 줄 고치는 것을 못 막는데, 감사 로그는 바로 그것을 막으려고 있다.

**테스트가 강제 지점을 우회하면 그 사실을 적는다.** `PostgresTestBase` 의 정리가 트리거를 끄는 자리가 그 예고,
가드 자체를 따로 재는 테스트가 있어야 검증이 비지 않는다.

## 패키지

**자원 단위로 판다.** 관객·기획사 같은 사람 단위로 안 판다 — 같은 자원을 두 사람이 다루면 코드가 두 벌이 된다.

지금 있는 것: `account` · `audit` · `auth` · `consent` · `error` · `event` · `health` · `idempotency` · `notification` · `observability` · `outbox` · `payment` · `reservation` · `settlement`.

**의존 방향은 `payment → reservation → event → settlement`, 그리고 전부 `outbox`·`idempotency`·`audit`·`error` 로.** 취소 입구가 `payment` 에 있고 회차 종료가 `reservation` 에 있는 이유다 — 부르는 쪽이 아래로 간다.

**소비자(`notification`·`settlement`)는 봉투만 알고 서로 모른다**(`D11`). 알림이 죽어도 정산은 간다 — 그것이 소비자를 가른 값이다.

### 의존

**`error` 는 모두가 부르고 아무도 안 부르는 잎이다.** 거기서 밖으로 나가는 의존이 생기면 순환이 시작된다.

`ArchitectureTest.noPackageCycles` 가 막는다. 순환이 생기면 모듈을 쪼갤 때 막히는 자리가 되고,
어느 쪽을 먼저 빌드할지가 안 정해진다.

## 설정과 상수

| 무엇 | 어디 |
|---|---|
| 환경마다 갈리는 값 | `application.yml` 의 환경변수 |
| 코드가 정하는 값 | `companion object` 의 `const` |
| 여러 청크가 읽는 도메인 수치 | **ADR 0003** — 코드에 박기 전에 그 표를 본다 |

**값 옆에 출처를 적는다.** 법·표준에서 온 값이면 조문 번호를, 우리가 고른 값이면 ADR 번호를 붙인다.

## `public` 에는 근거가 있어야 한다

Kotlin 은 기본이 `public` 이다. **패키지 밖에서 안 쓰는 것을 열어 두지 않는다** — 아무도 안 쓰는 `public` 은
다음 사람에게 「여기로 들어와도 된다」는 신호라, 계층을 지나 부르는 코드가 그 자리로 들어온다.

가르는 것은 하나다: 밖에서 실제로 쓰나. 스프링이 부르는 것은 안 센다 — 컨테이너가 부르므로 밖에서 안 쓰는 것이 정상이다.

## 불변식

**절대 깨지면 안 되는 등식**이다. 계산 방법이 아니라 **계산이 틀렸는지 아는 방법**이다.

### 어디에 거나

「강제 지점」 순서를 그대로 따른다. 위에서부터 되는 것을 고른다.

| 지점 | 쓸 수 있는 경우 | 이 저장소의 예 |
|---|---|---|
| `check` 제약 | 한 행 안에서 끝난다 | 살아 있는 계정에 이메일이 있다, 가격 ≥ 0 |
| 부분 유일 인덱스 | 조건이 붙은 유일성 | 살아 있는 행만 이메일이 유일하다 |
| 트리거 | 다른 행·테이블을 봐야 한다 | 감사 로그는 고칠 수 없다 |
| 테스트 | 위 셋으로 못 건다 | 환불 금액 공식 |

**한 행 안에서 끝나는 것을 테스트로 검증하지 않는다.** 테스트는 돌릴 때만 막고 제약은 언제나 막는다.

### 새 불변식을 찾는 자리

**합계를 저장하는 순간**이다. 합계는 원본과 어긋날 수 있는 유일한 종류의 값이다.
예매 합계와 좌석별 가격의 합이 그 첫 자리가 된다(청크 13).

## 규칙의 우선순위

규칙이 서로 어긋날 때 무엇이 이기나. **축이 둘이고 섞으면 안 된다.**

### 축 1 — 출처. 충돌하면 무엇이 이기나

| 순위 | 출처 | 어기면 | 우리가 고칠 수 있나 |
|---|---|---|---|
| 1 | **법·규정** | 과태료·형사·계약 무효 | 못 고친다 |
| 2 | **표준·규격** | 남의 시스템과 안 붙는다 | 못 고친다 |
| 3 | **프로젝트 규약** | 아무 일도 안 난다 | 고친다 — 단 문서를 먼저 |
| 4 | **업계 관례** | 아무 일도 안 난다 | 근거만 대면 버린다 |

**가이드를 통째로 받거나 버리지 않는다. 항목마다 근거를 댄다.** 생성형 도구가 들고 오는 기본값도 4번이다.

### 플랫폼 사실은 순위 다툼에 안 들어온다

Postgres 가 `length` 를 글자로 세는 것, `changeSessionId()` 가 세션 생성 시각을 안 바꾸는 것 같은 것들이다.
**법도 표준도 규약도 관례도 아니다.**

자리가 없는 이유는 **어길 수가 없어서**다. 위 넷은 「어기면 무슨 일이 나나」로 줄을 세우는데
플랫폼 사실은 어기는 것이 아니라 **모르면 틀리는 것**이다.

| | 출처 넷 | 플랫폼 사실 |
|---|---|---|
| 성격 | 지킬지 말지를 고른다 | **전제다.** 고를 것이 없다 |
| 어긋나면 | 위 순위로 이긴 쪽 | **규약이 진다** |
| 어디에 적나 | 이 문서와 D 문서들 | `stack.md` |

### 축 2 — 강제 지점. 어디에 걸어야 실제로 막히나

| 순위 | 지점 | 언제 걸리나 |
|---|---|---|
| 1 | **타입·스키마 구조** | 컴파일·설계 시점. 어길 방법이 없다 |
| 2 | **DB 제약** | 쿼리 실행 순간 |
| 3 | **앱 검증** | 요청 처리 중. **새 입구가 생기면 빠뜨린다** |
| 4 | **테스트** | 돌릴 때만 |
| 5 | **주석·문서** | 사람이 읽을 때만 |

**DB 제약은 출처가 아니라 강제 지점이다.** 우리가 만든 것이라 출처로는 3번인데, 막는 즉시성은 법보다 세다 —
법은 몇 년 뒤에 걸리고 제약은 0.1초 뒤에 걸린다.

### 안 나가게 하는 것도 강제 지점이 있다

위 표는 **잘못 들어오는 것**을 막는 순서다. **잘못 나가는 것**은 순서가 따로다.

| 순위 | 지점 | 언제 걸리나 |
|---|---|---|
| 1 | **계약에 칸이 없다** | 응답 `data class` 에 필드를 안 만든다. 실을 방법이 없다 |
| 2 | **마스킹 규칙** | 요청 처리 중. 새 컬럼을 더할 때 빠뜨린다 |
| 3 | **테스트** | 돌릴 때만 |

**갈리지 않는데 마스킹을 걸지 않는다.** 아무에게도 안 나갈 값이면 응답 타입에서 빼는 편이 낫다 —
규칙이 하나 줄고, 새 컬럼을 더할 때 빠뜨리는 실수가 성립하지 않는다.

### 두 축을 합치면

**출처가 위일수록 반드시 지키고, 지키는 자리는 가능한 한 아래로 내린다.**

```
RFC 5321 주소 254 옥텟        (출처 2위)
  → EmailAddress 애너테이션    (강제 지점 3위)
    → account_email_length_check  (강제 지점 2위)
```

문서에만 적힌 규칙은 안 지켜진다. **내릴 수 있는 데까지 내린 다음, 못 내린 것만 문서에 남긴다.**

## 접근성

**화면을 만드는 청크에 걸린다.** 출처는 법이다 — 장애인차별금지법 제20조·제21조가 정보 접근에서의 차별을 금지하고,
기술 기준은 국가표준 KWCAG 2.2 다. 민간 사업자도 의무 대상이고 단계적 적용은 끝났다.

**나중에 붙이지 않는다.** 좌석도를 SVG 로 정한 것이 그 결과다(ADR 0003) — 마크업을 먼저 고르면 접근성이 따라오고,
Canvas 로 그린 뒤에 붙이려면 그림과 별개인 DOM 목록을 새로 만들어 유지해야 한다.

## 이 문서를 고칠 때

다음 사람이 그것을 관례로 본다.
