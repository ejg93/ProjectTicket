# 식별자 규약

내부에서 쓰는 ID 와 바깥에 내보내는 번호를 어떻게 가르는지 정한다. 코드는 18(`TicketService`)·13(`IdempotencyKeys`)에 있다.

## 두 가지를 가른다

| | 내부 ID | 노출 번호 |
|---|---|---|
| 예 | `reservation.reservation_id = 1042` | `20260925-7QX4M2` |
| 타입 | `bigint generated always as identity` | `text` |
| 쓰는 곳 | 외래키, 조인, 인덱스, **URL** | 화면·CS·입장 |
| 성질 | 순번 | 순번 정보가 없다 |

## 순번을 노출하면 새는 것

순번은 **총량과 증가 속도**를 알려준다. 예매 번호가 `10000` 에서 한 달 뒤 `13500` 이면 한 달 예매가 3,500건이고, 티켓가를 곱하면 매출이 추정된다.
2차대전 때 노획한 전차의 일련번호로 독일의 생산량을 추정한 데서 **독일 전차 문제**라고 부른다.

이 저장소는 그 대응을 둘로 나눈다. **URL 에 내부 ID 를 쓰되 남의 것은 404 로 숨긴다**(`D5` 「403 이냐 404 냐」 — 예매·결제·티켓). 번호를 훑어도 자기 것 말고는 전부 없는 것으로 보여서 총량이 안 샌다.
그리고 **사람 손에 쥐어지는 것**(티켓)만 노출 번호를 따로 둔다.

## 자원별 노출 방식

| 자원 | 노출 | 왜 |
|---|---|---|
| 티켓 | **`ticket_number`** | 입장·CS 에서 사람이 부르는 값이다. 순번이면 판매량이 샌다. **URL 에는 안 쓴다** — 티켓은 예매 아래(`/api/reservations/{id}/tickets`)로만 읽는다 |
| 예매·결제·환불 | 내부 ID | 본인만 본다(404). 번호를 따로 두면 조회 입구가 둘이 된다 — 부르는 곳이 화면 하나뿐이라 안 만든다 |
| 회차·공연·좌석 | 내부 ID | 공개 목록이라 총량이 목록에서 세어진다. 숨길 것이 없다 |
| 계정 | 내부 ID | 계정 조회는 권한이 막는다 |
| 기획사·등급 | `code` | 사람이 정하는 값이 이미 있다 |

**노출 번호로 조회하는 경로를 만들지 않는다.** 번호를 알면 보이는 입구는 번호가 곧 인증이 되는 것이다. 조회는 로그인한 사용자의 소유 판정을 거친다.

## 티켓 번호

```
20260925-7QX4M2
└──날짜──┘ └난수┘
```

| 부분 | 내용 | 왜 |
|---|---|---|
| 날짜 8자리 | 발권일(KST) | CS 용. 고객도 아는 정보라 노출돼도 무해하다 |
| 구분자 | 하이픈 | 눈으로 읽기 쉽다 |
| 난수 6자리 | `2-9` 와 `O`·`I` 를 뺀 알파벳 — 32자 | 순번을 가린다. 전화로 번호를 불러줄 때 잘못 듣는 것을 줄인다 |

**`SecureRandom` 을 쓴다.** `Random` 은 앞의 출력 몇 개로 다음 값이 계산된다. `32^6 ≈ 10억` 이라 충돌이 드물지만 0 이 아니고, 유일 인덱스가 판정하면 다시 뽑는다 — 3회까지, 그래도 겹치면 오류다(난수가 아니라 코드가 틀린 것이다).

**형식은 제약이 든다** — `ticket_ticket_number_format_check`. 규칙을 적은 문서가 그 규칙을 어긴 예시를 든 적이 있다(`1` 이 든 예시). 예시를 지어낼 때 이 집합을 확인한다.

## 내부 ID

`bigint generated always as identity` 다. UUID 를 기본키로 쓰지 않는다 — 16바이트라 외래키가 많은 스키마에서 인덱스가 두 배가 되고, 조인·정렬이 정수 비교보다 느리다.
UUIDv7(RFC 9562)이 인덱스 지역성 문제를 풀지만 **ID 를 여러 곳에서 만들 일이 없다.** 인스턴스가 셋이 돼도(33) DB 는 하나다.

## 멱등키

선점·결제 두 입구가 받는다(`D4` 「멱등키」). **클라이언트가 만든 UUIDv4** 고 `IdempotencyKeys` 가 형식을 본다 — 아니면 400.
계정별로 유일하고 남의 키와 겹쳐도 상관없다. 개인정보를 넣지 않는다 — 키는 로그에 남는다.

## 이 문서를 고칠 때

노출 번호를 새로 두려면 「부르는 곳」을 먼저 센다 — 화면 하나면 안 만든다. 형식을 바꾸면 `V11` 의 check 와 `TicketService.ALPHABET` 을 같이 본다.
