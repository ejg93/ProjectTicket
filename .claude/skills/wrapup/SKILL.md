# 마무리

**이 세션에서 친 청크 전부를 한꺼번에 정리한다.** 청크마다 안 한다. 세션이 길면 중간에도 한다.

| 무엇 | 무엇을 남기나 |
|---|---|
| 청크를 센다 | 커밋을 훑어 이 묶음의 청크가 `PLAN.md`·`PROGRESS.md` 에 다 닫혔나 |
| 고칠 것을 찾는다 | 아래 대조 다섯 |
| 더할 청크를 찾는다 | 드러났는데 어느 청크도 안 다루는 것 → `PLAN.md` 에 행 |
| 독립 에이전트에게 묻는다 | 아래 |
| PR 을 연다 | 아래 |

## 대조 다섯

**먼저 `bash scripts/doc-lint.sh`.** 기계가 잡는 것을 사람이 또 안 훑는다. 아래는 기계가 못 잡는 것이다.

| 무엇을 보나 | 어떻게 |
|---|---|
| 문서가 부르는 것이 있나 | `V번호`·클래스·테스트 이름이 실물과 맞나 |
| 미룬 것이 청크에 실렸나 | 「나중에」로 끝난 문장에 어느 청크인지 적혔나 |
| 결정이 코드와 같나 | 문서가 고른 값과 설정·상수가 어긋나지 않나 |
| **이번 결정끼리 부딪치나** | 청크 A 가 정한 것을 청크 B 가 어기지 않나. 참조 대조로는 안 걸린다 |
| **말한 축과 편 축이 같나** | 시작 세 줄에서 「제약으로 내린다」고 해 놓고 테스트로 끝냈나 |

고치는 것은 지금 규칙으로 읽히는 글뿐이다. **이력은 그때의 사실이라 안 고친다.**

## 독립 에이전트에게 먼저 묻는다

같은 눈으로 다시 읽으면 맹점이 남는다. PR 을 열기 전에 서브에이전트 하나를 띄운다.

| | 무엇 |
|---|---|
| 주는 것 | `git diff main...HEAD` · `CLAUDE.md` 「청크 하나를 어떻게 치나」 · 이 묶음 청크의 시작 세 줄(이력에서) |
| **안 주는 것** | 이 세션의 대화 |
| 묻는 것 | ① diff 안의 결정끼리 부딪치는 것 ② 시작 세 줄이 말한 축·강제 지점과 diff 가 편 것이 다른 자리 ③ 좌석 상태를 건드린 자리에 조건부 UPDATE 가 아닌 것이 있나 |
| 받는 것 | 「없다」 한 줄이거나 `파일:줄 — 무엇 — 어느 규칙` |

나온 것은 「찾은 것을 어떻게 처분하나」 셋으로 간다. **「오탐이다」도 처분이고 근거를 적는다.** 이력에 「독립 리뷰: 지적 N, 처분 …」을 남긴다.

## 찾은 것을 어떻게 처분하나

| 규모 | 어떻게 |
|---|---|
| 글 한 줄·값 하나·빠뜨린 호출 | 지금 고친다 |
| 이미 있는 청크가 다룰 것 | 그 행에 적는다 |
| 설계 결정이 필요하거나 파일이 여럿 | 새 청크를 세운다 |

기준은 「지금 고치면 마무리가 안 끝나나」다. 결정이 필요하면 청크다. 어느 쪽이든 이력에 밝힌다.

## PR 을 여기서 연다

작업 가지(`work/<날짜>`)에 청크가 쌓여 있고 마무리가 그 묶음을 **PR 하나로** 낸다.

| 무엇 | 어떻게 |
|---|---|
| 앞에 | `bash scripts/verify.sh --full` 초록. push hook 이 요구한다 |
| 본문 | 청크마다 시작 세 줄. `.github/pull_request_template.md` |
| 머지 | `--merge`. squash 는 청크 다섯을 한 커밋으로 만들어 하나만 못 되돌린다 |
| 언제 | CI 초록 뒤 |

회차를 이력에 적는다(`마무리 1차`). 대상은 그때까지 친 청크 전부다.
