# 점검

**저장소 전체를 한 축으로 훑는 절차다.** 언제 여는지와 왜 청크와 같은 급인지는
`CLAUDE.md` 「점검」이 정한다.

## 왜 하나 — 읽기로는 안 걸린다

`점검 F`(2026-08-20)가 사흘치를 훑어 **서른둘**을 찾았는데
**그중 열하나가 「그 문서를 읽고도 안 걸린 것」**이었다(표준 여덟·관례 셋).

**규칙을 읽는 것과 지켜졌는지 훑는 것은 다른 일이다.** 예열이 축을 골라 줘도 청크가 길어지면
흐려지고, 마무리는 그날 친 것만 본다 — **아무도 안 건드린 자리는 어느 쪽에도 안 걸린다.**

## 같은 질문만 반복해서 읽지 않는다

**같은 눈으로 다시 읽으면 쓴 사람의 맹점이 그대로 남는다**(2026-09-03). 문서 감사 뒤
오늘 수정분을 세 각도로 다시 봤다 — **그 지시를 문자 그대로 실행해 보는 축**(트리거를
받은 것처럼 시뮬레이션), **컨텍스트 없는 새 에이전트에게 diff만 주고 판단시키는 축**,
**뭐가 틀렸나가 아니라 뭐가 빠졌나를 묻는 축**(범위를 넓혀 다른 자리도 훑는다). 셋 다
하나씩 잡았고, **그중 가장 큰 것**(`PLAN.md` 에 남아있던 것과 같은 유형의 표 파편)은
셋째 축이 잡았다 — 정적으로 정확성만 캐묻는 눈으로는 "범위 밖이라 아무도 안 본 자리"가
안 보인다.

**점검을 여러 줄 돌릴 때 정적 정독 하나로 그치지 않는다.** 위 세 축(실행·독립 검증·누락)
중 최소 하나는 섞는다 — 무엇을 섞을지는 그날 뭘 놓치기 쉬운지로 고른다.

## 코드를 안 읽고 요건표만 보고 판정하지 않는다

**점검이 낸 것도 틀릴 수 있다.** `점검 F` 가 「프레임워크 오류의 `type` 이 `about:blank` 로 나간다」고
적었는데 사실이 아니었다 — 핸들러가 이미 갈아 끼우고 있었다. **진짜 문제는 반대쪽**이었다:
갈아 끼우면서 405·415·깨진 JSON 을 전부 한 이름으로 줬다. 고칠 자리는 같고 방향만 정확해졌다.

**같은 오판이 강제 지점 줄에서도 났다.** `B4` 는 「컬럼 하나가 뜻을 둘 가진다」였는데
**마이그레이션 주석이 이미 답을 적어 뒀다** — 「이쪽은 계산된 결과라 비어 있을 수 없다」.
스키마만 훑으면 되는 것처럼 보이지만 **왜 그 모양인지는 주석에만 있는 경우가 있다.**

**두 번째 사례가 `점검 J` 다**(2026-09-10 확인). 「약정 유무가 묶음에 안 박제된다」고 `14c-1` 을 세웠는데
**`V35` 가 이미 한 것**이었다 — `seller_order.agreed_lead_days`, null 이 「약정 없음」이고 제약 둘에
`ShipDeadlineTest` 가 양쪽을 잡는다. 그 점검이 읽은 것은 `coding-rules.md` 의 처분 문장이었고
**마이그레이션을 안 열었다.** 앞의 둘과 같은 모양이다 — 글을 읽고 코드를 안 읽으면 판정이 뒤집힌다.

**그래서 찾은 것마다 무엇을 보고 그렇게 판정했는지 같이 적는다.** 근거가 없으면 다음 사람이
그 판정을 다시 잴 수 없고, 틀린 판정이 고쳐진 뒤에도 이유가 안 남는다.

## 축이 둘이다

**한 규칙에 물을 수 있는 것이 둘이라서** 축도 둘이다.

| 축 | 묻는 것 | 성질 |
|---|---|---|
| **출처**(가로) | **누가 시켰나** | 순위다 — 충돌하면 위가 이긴다 |
| **강제 지점**(세로) | **어디서 막나** | 강도다 — 왼쪽일수록 안 지킬 방법이 없다 |

```
              타입   제약   앱검증  테스트  문서
   법          ·      ·      ·      ·      ·
   표준        ·      ·      ·      ·      ·
   규약        ·      ·      ·      ·      ·
   관례        ·      ·      ·      ·      ·
```

둘 다 `D23` 의 「규칙의 우선순위」가 이미 정한 목록이다 — **여기서 새로 만들지 않는다.**
가로가 축 1, 세로가 축 2다.

**세로가 하나 더 있다.** 위 다섯은 **잘못 들어오는 것**을 막는 사다리고,
`D23` 「안 나가게 하는 것도 강제 지점이 있다」가 **잘못 나가는 것**의 사다리를 따로 든다
(계약 칸·마스킹·테스트). **세로를 훑을 때 둘 다 센다** — 마스킹은 이 사다리에만 있다.

**섞으면 답이 없는 물음이 생긴다.** 「법 vs DB 제약, 뭐가 이기나」에 답이 안 나오는 이유는
**DB 제약이 법과 싸우는 것이 아니라 법을 지키는 도구**여서다. 2026-08-23 이전에는
「축 여섯」이 그 둘을 한 목록에 담고 있었다.

## 한 번에 줄 하나를 고른다

**칸 스물을 다 보지 않는다.** 이미 그렇게 돌고 있었다 — `점검 A` 가 법 줄(가로),
`점검 B` 가 제약 줄(세로)이다.

| 고른 줄 | 묻는 것 |
|---|---|
| 가로 하나(예: 법) | **그 출처의 요건이 전부 어딘가에 박혔나** |
| 세로 하나(예: 제약) | **그 자리에 걸린 것이 다 제 역할을 하나** |

**제일 위험한 칸은 「법 × 문서」다.** 법은 반드시 지켜야 하는데 문서는 사람이 읽을 때만 걸린다 —
2026-08-23 에 둘을 찾았다: `R34` 는 게시 중단이 `psql` 로만 됐고, `R36` 은 약관 문구에만 있었다.

## 어디서 시작하나

**방향이 반대다.** 가로는 요건표에서 코드로 내려가고, 세로는 코드에서 출처로 올라간다.

```
가로(출처)   요건표  →  코드     「이 요건이 어디에 박혔나」   ← 없는 것을 찾는다
세로(강제)   코드    →  출처     「이건 왜 여기 걸렸나」       ← 잘못 걸린 것을 찾는다
```

**가로는 반대로 못 간다.** 빠진 요건은 **코드에 흔적이 없어서** 어느 파일을 열어도 안 보인다 —
`점검 A` 의 `R1`(셀러 신원 표시)이 그랬다.

| 줄 | 시작 파일 | 세는 단위 | 2026-08-23 기준 |
|---|---|---|---|
| 가로 · 법 | `commerce-compliance.md` 요건표. **`bash scripts/req-coverage.sh` 를 먼저 돌린다**(`2v`) — 테스트가 안 부르는 R 이 나온다 | 요건 `R번호` | 37 |
| 가로 · 표준 | `external-references.md` | 인용한 RFC·W3C | |
| 가로 · 규약 | `document-map.md` 의 D 목록 | 문서가 정한 것 | 26 문서 |
| 가로 · 관례 | `stack.md`·`coding-rules.md` | 따르거나 버린 항목 | |
| 세로 · 타입 | **`db/migration/*.sql` 의 `check (X in (...))`** | 닫힌 값 목록 | 27 |
| 세로 · 제약 | `db/migration/*.sql` | 이름 붙은 제약 | 154 |
| 세로 · 앱 검증 | 서비스·검증기 | 검사 호출 | |
| 세로 · 테스트 | **`testing-strategy.md`(D15)** | 아래를 본다 | `@Test` 942 |
| 세로 · 문서 | `doc/reference/` | 문서 | 26 |

**「타입」 줄은 제약에서 시작한다**(2026-08-29 `점검 H`). 타입 124개를 훑으면 「이 타입이 왜 있나」를
묻게 되는데, 정작 알고 싶은 것은 **「타입으로 막을 수 있는데 안 막은 자리」**다. 그건 타입 쪽에 흔적이 없다 —
**DB 가 값 목록을 닫아 둔 자리에서 「Java 가 이 값을 무슨 타입으로 드나」**를 물어야 보인다.

**「테스트」 줄만 방향이 또 뒤집힌다.** 942개를 못 읽는다 — `D15` 가 「무엇을 어느 층에서
검증한다」고 정해 놨으니 **그 목록에서 내려가며 「이건 왜 아직 테스트에 있나」**를 묻는다.
테스트는 **돌릴 때만** 걸리는 4순위라, 거기 있는 것은 **더 아래로 못 내린 것**이거나 **안 내린 것**이다.

## 걷는 순서

```
1. PROGRESS.md 「점검 — 어디까지 봤나」에서 줄을 고른다  →  마지막으로 본 날이 오래된 줄
2. 위 표의 시작 파일에서 실물을 뽑는다
3. 하나씩 셋을 묻는다
     ├ 무엇을 막나
     ├ 출처가 뭐냐            (법? 표준? 규약? 관례?)  ← 여기서 다른 축과 만난다
     └ 실제로 도나            ← 「걸려 있다」와 「돈다」는 다르다
4. 처분한다                                 →  지금 고치거나 청크로
5. 그 표를 고치고 분할표 행을 닫는다
```

**3번 셋째가 이미 값을 했다** — `V63` 의 지연 트리거 둘은 **걸려 있는데 한 번도 안 돈다.**
지연이라 커밋 때 보는데 테스트는 롤백한다. **목록으로는 초록이고 실물은 0회다**(`stack.md`).

## 축이 아닌 것도 훑는다

**격자에 안 들어가지만 값이 있는 단위**가 있다. 축과 갈라 적는다.

| 단위 | 무엇 | 예 |
|---|---|---|
| **대상 구역** | 한 구역을 통째로 | `점검 D` 프론트 |
| **바깥 근거** | 인용한 자료가 아직 유효한가 | `점검 E` 기준 자료 |
| **계획 자체** | 청크가 겹치거나 없는 것을 가리키나 | `점검 G` 묶을 청크 검토 |
| **품질 게이트** | 걸어 둔 게이트가 아직 제 역할을 하나 | `D25` — 제외가 늘었나, 신호가 얇아졌나, **한 번이라도 돌았나**, **「부순 날」이 비어 있나** |
