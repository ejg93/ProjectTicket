# 예열

**세션을 여는 절차다.** 코드를 안 건드리고 아래 셋을 하고 멈춘다.

1. **규칙의 뼈대를 훑는다** — `doc/reference/coding-rules.md` 의 「규칙의 우선순위」 절만. 통짜로 안 읽는다
2. **「현재 상태」는 SessionStart hook 이 넣어 줬다.** `PROGRESS.md` 를 다시 안 읽는다
3. **다음 청크에 걸리는 축을 골라 말한다.** 아래 표

## 축을 고른다

청크 성격이 축을 정한다. **출처**(무엇이 시켰나)와 **강제 지점**(어디서 막나) 둘을 같이 고른다.

| 청크가 무엇을 건드리나 | 펴는 출처 | 내릴 강제 지점 |
|---|---|---|
| 좌석 상태·선점·확정 | **`D4` 동시성 규약** + 표준(SQL 격리 수준 원문) | **제약·조건부 UPDATE** — 앱 검증으로 끝내지 않는다 |
| 응답 계약·상태 코드 | 표준(RFC 9457 등 원문. 기억으로 안 쓴다) + `D5` | 타입·스냅샷 테스트 |
| 스키마·마이그레이션 | 그 컬럼을 시킨 문서(`D2`·`D3`) | **제약** — 막을 수 있는 가장 낮은 자리 |
| 대기열·토큰 | `D12` + `D9`(위조·재사용) | TTL·필터·테스트 |
| 이벤트·소비자 | `D11` + 표준(at-least-once) | 멱등키 유일 제약 |
| 화면 | `D17` + WCAG | lint(접근성 규칙) |
| 새 라이브러리 | 관례(따르든 버리든 근거를 적는다) | 설정·문서 |
| 코드를 쓰는 모든 청크 | `D14`·`D15` — 늘 걸린다 | |

**이식 머리말이 붙은 문서를 펼 때는 예시를 안 믿는다** — 원칙만 가져오고, 예시가 쇼핑 도메인이면 그 자리에서 밝힌다.

## 예열이 못 하는 것

기억은 하루를 못 간다. 예열이 축을 골라 줘도 청크가 길어지면 흐려진다.
그래서 결론은 늘 하나다 — **기억에 맡길 것을 강제 지점으로 내린다.** 「다음에 조심한다」로 끝나는 예열은 안 한 것과 같다.
