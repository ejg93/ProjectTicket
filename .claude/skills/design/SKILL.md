# 설계

**번들(실행 세션 하나가 연달아 치는 청크 4~8개) 앞에 한 번 한다.** 코드를 안 건드린다. plan mode 로 연다.
결과물은 `PLAN.md` 의 행이다 — 실행 세션(Opus)이 그 행만 읽고 **멈추지 않고** 간다.

근거는 ProjectShop 번들 A(2026-09-23 밤, 설계 `d362e8d` → 여덟 청크 2시간, 정지 0)다.

## 절차

| 순서 | 무엇 | 남기는 것 |
|---|---|---|
| 1 | 번들 후보를 고른다 — 선행이 `완료` 인 미착수 행에서 4~8개. 순서는 `CLAUDE.md` 「무엇부터」. 사슬(`29→30→31` 꼴)은 번들 앞쪽에 | 번호 목록 |
| 2 | 행마다 갈림을 뽑는다. 사실을 먼저 적고 갈리는 자리를 (가)/(나) 로 낸다 | **사용자에게 한 번에 묻는다.** 행마다 안 묻는다 |
| 3 | 답을 행에 박는다 | 아래 「행 형식」 |
| 4 | 설치가 필요한 행을 골라낸다(kind·helm·k6·Playwright) | 승인 목록 한 줄. 실행 전에 사용자가 `!` 로 깐다 |
| 5 | 마이그레이션·설정 파일을 고치라는 행은 그 파일이 이미 `main` 에 머지됐나 본다 | 머지된 `V*` 는 못 고친다(체크섬). 새 번호로 적는다 |
| 6 | 커밋한다 — `docs: 설계 — 번들 N` | 문서 청크 하나로 센다 |

## 행 형식

미착수 행의 넷(축·강제 지점·건드리는 자리·닫힘)에 셋이 는다.

| 칸 | 무엇 | 예 |
|---|---|---|
| **사실** | 지금 코드·문서가 무엇이라 하나. 결정의 근거 | 「`Location` 이 가리키는 `GET` 이 없어 404」 |
| **결정** | 누가 언제 무엇을 골랐나 | 「2026-09-25 사용자 (가)」 |
| **번호 절차** | ①~⑦, 파일 단위. 마지막은 시험 | 「① `V10__x.sql` ② `XService` ③ 시험 — …」 |
| 축·강제 지점·건드리는 자리 | 그대로 | |
| 닫힘 | 절차의 시험 번호 | 「③ 초록」 |
| **실패 사다리** | 절차가 안 풀릴 때 실행이 멈추지 않고 갈 길 | 「AES-GCM 이 표준 API 로 안 풀리면 접고 이력에 적는다」 |

**절차 3~7단계가 청크 하나다.** 8 이상이면 행을 둘로 나눈다. 레인은 하나 — API 와 화면은 행이 다르다.

## 실행 세션이 이 행을 어떻게 쓰나

- 행대로 간다. 행과 다르게 가면 **그 행에 적고 계속**
- 행에 없는 갈림 → 실패 사다리에 있으면 그대로. 없으면 정하고 이력에 「정한 것(계획 밖)」. **행당 둘까지** — 셋째부터는 WIP 커밋하고 다음 행
- 번들 끝 보고(`/wrapup`)가 계획 밖 결정·WIP·신규 행을 모아 사용자에게 낸다

## 설계가 못 하는 것

행이 아무리 자세해도 실행 중 드러나는 것은 남는다. ProjectShop 번들 A 는 여덟 중 넷이 행과 다르게 갔다.
설계는 **멈춤**을 없애는 것이지 **다름**을 없애는 것이 아니다.
